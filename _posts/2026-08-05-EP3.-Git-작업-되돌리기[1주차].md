### <strong>#작업 되돌리기</strong>

지금까지 수정한 파일을 스테이지에 올리고 커밋하는 방법까지 공부하였다. 이제 스테이지에 올렸던 파일을 내리거나 커밋을 취소하는 등 각 단계로 돌아가는 방법을 알아보자.

#### <strong>작업 트리에서 수정한 파일 되돌리기 - git restore</strong>

지난번에는 수천 줄이 넘는 코드를 수정했을 때 수정한 부분이 어디인지 찾는 방법을 알아보았다. 이번에는 파일을 수정한 후 코드가 정상으로 동작하지 않거나 다른 이유로 수정한 것을 취소하고 가장 최신 버전 상태로 되돌려야 할 때 작업 디렉터리에서 수정한 내용을 되돌리는 방법을 알아보자. 명령으로는 restore를 사용한다. (기존 checkout 명령과 동일) 

한번 실습으로 자세히 알아보겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="691" data-origin-height="204"><span data-url="/assets/images/posts/0aa34fdb9771eb715bb85a364b929a49df0186f3.png" data-phocus="/assets/images/posts/0aa34fdb9771eb715bb85a364b929a49df0186f3.png"><img src="/assets/images/posts/0aa34fdb9771eb715bb85a364b929a49df0186f3.png" loading="lazy" width="691" height="204" data-origin-width="691" data-origin-height="204"></span></figure>

지난번에 실습했던 hello.txt 파일을 그대로 가져와서 3번째 줄을 'Korea'로 바꿔준 뒤 저장하였다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="515" data-origin-height="138"><span data-url="/assets/images/posts/57aee57e4e35d4f3426fc6fcd7f58ecb8ea1a23e.png" data-phocus="/assets/images/posts/57aee57e4e35d4f3426fc6fcd7f58ecb8ea1a23e.png"><img src="/assets/images/posts/57aee57e4e35d4f3426fc6fcd7f58ecb8ea1a23e.png" loading="lazy" width="515" height="138" data-origin-width="515" data-origin-height="138"></span></figure>

내용을 변경해 줬으니 git status 명령을 사용해 상태를 확인해 주었다. hello.txt가 수정되었지만 아직 스테이지에 올라가 있지 않는 상태인 것을 확인할 수 있다. 또한 (use "git restore &lt;file&gt;..." to discard changes in working directory)의 메시지를 보면 작업 디렉터리의 변경 사항을 취소하려면 restore 명령을 사용하라고 되어 있다.

이번에는 hello.txt의 수정 사항을 취소해 보자.

> git restore \[파일 이름\]
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="365" data-origin-height="51"><span data-url="/assets/images/posts/3c09b363334a55fa4e5dc3e30ea1d90333c6681e.png" data-phocus="/assets/images/posts/3c09b363334a55fa4e5dc3e30ea1d90333c6681e.png"><img src="/assets/images/posts/3c09b363334a55fa4e5dc3e30ea1d90333c6681e.png" loading="lazy" width="365" height="51" data-origin-width="365" data-origin-height="51"></span></figure>

git restore 명령 다음에 한 칸 띄고 파일 이름을 쓰면 된다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="517" data-origin-height="147"><span data-url="/assets/images/posts/80133678f577a9d63c2c3d2d7098a8a177d8d299.png" data-phocus="/assets/images/posts/80133678f577a9d63c2c3d2d7098a8a177d8d299.png"><img src="/assets/images/posts/80133678f577a9d63c2c3d2d7098a8a177d8d299.png" loading="lazy" width="517" height="147" data-origin-width="517" data-origin-height="147"></span></figure>

restore 명령이 정상으로 처리되면 그 파일의 내용이 즉시 바뀐다. 즉, 처음에 수정한 'Korea'가 취소되고 다시 'very Happy!!'로 바뀐다.

#### <strong>스테이징 되돌리기 - git restore --staged</strong>

이번에는 수정된 파일을 스테이징까지 했을 때 스테이징을 취소하는 방법을 알아보자. 스테이징을 취소할 때도 restore 명령을 사용한다. 다만 여기서 옵션이 하나 추가된다. 이번에는 실습하면서 만들었던 hello2.txt 파일을 사용해 보겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="522" data-origin-height="121"><span data-url="/assets/images/posts/1be954f95a43e20deaec54ff18ac18962589f6b2.png" data-phocus="/assets/images/posts/1be954f95a43e20deaec54ff18ac18962589f6b2.png"><img src="/assets/images/posts/1be954f95a43e20deaec54ff18ac18962589f6b2.png" loading="lazy" width="522" height="121" data-origin-width="522" data-origin-height="121"></span></figure>

기존 hello2.txt파일의 있는 내용을 모두 삭제하고 '안녕 C언어'를 입력한 후 저장해 주었다. 이후 git add 명령으로 hello2.txt 파일을 스테이지에 올린 후 git status 명령으로 파일 상태를 살펴보았다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="386" data-origin-height="101"><span data-url="/assets/images/posts/a541fe90b078743486758b49f85c0d90b7884bbb.png" data-phocus="/assets/images/posts/a541fe90b078743486758b49f85c0d90b7884bbb.png"><img src="/assets/images/posts/a541fe90b078743486758b49f85c0d90b7884bbb.png" loading="lazy" width="386" height="101" data-origin-width="386" data-origin-height="101"></span></figure>

상태 메시지에서 (use "git restore --staged &lt;file&gt;..." to unstage)를 보면 스테이지에서 내리려면 git restore --staged &lt;file&gt; 명령을 사용하라고 되어 있다. 해당 옵션에 대해 더 자세히 알아보자.

스테이징을 취소할 때는 restore 명령 뒤에 --staged 옵션을 붙인다. 이 옵션만 사용하면 스테이지에 있는 모든 파일을 한꺼번에 되돌릴 수 있고, --staged 옵션 뒤에 파일 이름을 넣으면 해당 파일만 골라서 되돌릴 수 있다.

그럼 한번 스테이지에 있는 hello2.txt를 내려 보겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="520" data-origin-height="143"><span data-url="/assets/images/posts/09fba1b04a2c3c484f7b2f53774d284f687a219e.png" data-phocus="/assets/images/posts/09fba1b04a2c3c484f7b2f53774d284f687a219e.png"><img src="/assets/images/posts/09fba1b04a2c3c484f7b2f53774d284f687a219e.png" loading="lazy" width="520" height="143" data-origin-width="520" data-origin-height="143"></span></figure>

git restore --staged hello2.txt 명령을 사용한 뒤 git status을 사용해 파일 상태를 확인해 보면, 파일이 아직 스테이지에 올라가기 전으로 돌아온 것을 확인할 수 있다.

#### <strong>최신 커밋 되돌리기 - git reset HEAD^</strong>

이번에는 수정된 파일을 스테이징하고 커밋까지 했을 때 가장 마지막에 한 커밋을 취소하는 방법을 알아보자. 이때 커밋을 취소하면 커밋과 스테이징이 함께 취소된다.

실습을 통해 알아보기 위해 hello2.txt 문서를 수정하겠다. 나는 '안녕 C언어' 문자 옆에 '!'를 2개 추가해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="363" data-origin-height="111"><span data-url="/assets/images/posts/d5bf4ceb7cea2edc9710a2cd68134e35bb50154a.png" data-phocus="/assets/images/posts/d5bf4ceb7cea2edc9710a2cd68134e35bb50154a.png"><img src="/assets/images/posts/d5bf4ceb7cea2edc9710a2cd68134e35bb50154a.png" loading="lazy" width="363" height="111" data-origin-width="363" data-origin-height="111"></span></figure>

다음으로 git commit 명령을 사용해 스테이징과 커밋을 함께 실행한다. 커밋 메시지는 "C언어로 변경"으로 하겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="457" data-origin-height="512"><span data-url="/assets/images/posts/d83236274a29633be1ff9c2d51d92a77624d6639.png" data-phocus="/assets/images/posts/d83236274a29633be1ff9c2d51d92a77624d6639.png"><img src="/assets/images/posts/d83236274a29633be1ff9c2d51d92a77624d6639.png" loading="lazy" width="457" height="512" data-origin-width="457" data-origin-height="512"></span></figure>

git log 명령을 사용해 제대로 커밋되었는지 확인해 보았다. 마지막 커밋 메시지가 'c언어로 변경'인 것을 보니 잘 커밋된 것 같다.

이제 최신 커밋을 되돌려보겠다. 이때 되돌리는 방법은 git reset 명령 다음에 HEAD^를 붙이면 된다. 이렇게 되돌리면 main의 최신 커밋도 취소되고 스테이지에서도 내려진다. 즉 작업 트리에만 파일이 남는 것이다. (스테이징만 취소할 때는 restore 명령을 사용하지만 커밋을 취소할 대는 reset 명령을 사용한다.)

> git reset HEAD^
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="256" data-origin-height="58"><span data-url="/assets/images/posts/57df7797d4cc0e677a41cf12bdc1f08065b066ba.png" data-phocus="/assets/images/posts/57df7797d4cc0e677a41cf12bdc1f08065b066ba.png"><img src="/assets/images/posts/57df7797d4cc0e677a41cf12bdc1f08065b066ba.png" loading="lazy" width="256" height="58" data-origin-width="256" data-origin-height="58"></span></figure>

명령을 입력해 주면 Unstaged changes after reset메시지가 나타난다. 즉, hello2.txt 파일의 커밋이 취소되고 스테이지에서도 내려졌다는 메시지를 남기고 있다.

정말 커밋이 취소되었을지 확인해 보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="444" data-origin-height="419"><span data-url="/assets/images/posts/14d8a7a74e1b9c3e323250fcc41e5c5869f4bd9a.png" data-phocus="/assets/images/posts/14d8a7a74e1b9c3e323250fcc41e5c5869f4bd9a.png"><img src="/assets/images/posts/14d8a7a74e1b9c3e323250fcc41e5c5869f4bd9a.png" loading="lazy" width="444" height="419" data-origin-width="444" data-origin-height="419"></span></figure>

git log 명령으로 확인해 보니 'c언어로 변경'인 커밋이 사라진 것을 볼 수 있다. 이 방법으로 커밋을 취소하면 커밋 전에 했던 스테이징도 함께 취소된다.

hello.txt 파일의 스테이징과 커밋은 취소했지만 작업 트리에는 아직 남아 있다. 이 상태에서 새로 스테이징하고 커밋을 해도 되고, 변경 내용을 취소해도 된다. 하지만 나는 restore 명령을 사용해 변경 내용을 취소하겠다.

> #추가 옵션 톺아보기  
>   
> git reset --soft HEAD^ : 커밋을 취소하고 파일을 staged 상태로 작업 디렉터리에 보관한다.  
> git reset --mixed HEAD^ : 커밋을 취소하고 파일을 unstaged 상태로 작업 디렉터리에 보관한다.  
> git reset HEAD^ : --mixed 옵션을 사용할 때와 같이, 커밋을 취소하고 파일을 unstaged 상태로 작업 디렉터리에 보관한다.
{: data-ke-style="style3"}

#### <strong>특정 커밋으로 되돌리기 - git reset 해시</strong>

깃에는 파일을 수정하고 커밋할 때마다 저장된 버전들이 쌓인다. 방금 살펴본 git reset HEAD^ 명령으로 최신 커밋을 되돌릴 수도 있지만 특정 버전으로 되돌려 놓고 그 이후 버전을 삭제할 수도 있다. 특정 커밋으로 되돌릴 대는 git reset 명령 다음에 커밋 해시를 사용한다. 이것도 한번 실습을 통해 자세히 알아보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="410" data-origin-height="94"><span data-url="/assets/images/posts/450b17908d52f52eccbaf4ef03dbf70ee6700543.png" data-phocus="/assets/images/posts/450b17908d52f52eccbaf4ef03dbf70ee6700543.png"><img src="/assets/images/posts/450b17908d52f52eccbaf4ef03dbf70ee6700543.png" loading="lazy" width="410" height="94" data-origin-width="410" data-origin-height="94"></span></figure>

 현재 있는 디렉터리에 rev.txt를 만들어 준 뒤 '1'를 입력한 후 저장해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="374" data-origin-height="79"><span data-url="/assets/images/posts/2de8a8830712eab998e5531e8fa74557a6389bf2.png" data-phocus="/assets/images/posts/2de8a8830712eab998e5531e8fa74557a6389bf2.png"><img src="/assets/images/posts/2de8a8830712eab998e5531e8fa74557a6389bf2.png" loading="lazy" width="374" height="79" data-origin-width="374" data-origin-height="79"></span></figure>

이후 rev.txt를 스테이지에 올린 후 커밋 메시지 "add 1"를 붙여 커밋해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="353" data-origin-height="124"><span data-url="/assets/images/posts/8b8bd3a7d131b9dbfd09961c1cb6c1d19b2d2adc.png" data-phocus="/assets/images/posts/8b8bd3a7d131b9dbfd09961c1cb6c1d19b2d2adc.png"><img src="/assets/images/posts/8b8bd3a7d131b9dbfd09961c1cb6c1d19b2d2adc.png" loading="lazy" width="353" height="124" data-origin-width="353" data-origin-height="124"></span></figure>

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="258" data-origin-height="67"><span data-url="/assets/images/posts/993c1c6b377cb060feb09532599930faca7aa62d.png" data-phocus="/assets/images/posts/993c1c6b377cb060feb09532599930faca7aa62d.png"><img src="/assets/images/posts/993c1c6b377cb060feb09532599930faca7aa62d.png" loading="lazy" width="258" height="67" data-origin-width="258" data-origin-height="67"></span></figure>

rev.txt를 한 번 더 수정해서 "2"를 추가한 후 저장하고, "add 2" 메시지와 함께 커밋하였다. 같은 방법으로 "3"을 추가하고 커밋하고, "4"를 추가하고 커밋하여 총 4번의 커밋을 진행해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="463" data-origin-height="433"><span data-url="/assets/images/posts/ee09cfca795341ee420f9c06460f231a5c8dddae.png" data-phocus="/assets/images/posts/ee09cfca795341ee420f9c06460f231a5c8dddae.png"><img src="/assets/images/posts/ee09cfca795341ee420f9c06460f231a5c8dddae.png" loading="lazy" width="463" height="433" data-origin-width="463" data-origin-height="433"></span></figure>

git log 명령을 사용해 지금까지 만든 커밋을 확인해 보았다. 커밋이 4개 있고 커밋마다 커밋 해시가 함께 나타나 있다. 이제 커밋 4개 가운데  "add 2"란느 메시지가 붙은 add2 커밋으로 되돌려보겠다. 즉, add 3 커밋과 add 4 커밋을 삭제하고 add 2 커밋을 최신 커밋으로 만들 것이다.

그런데 reset에서 커밋 해시를 사용해 되돌릴 때 주의할 점이 있다. 예를 들어 reset A를 입력한다면 이 명령은 삭제하는 것이 아닌 A 커밋 이후에 만들었던 커밋을 삭제하고 A 커밋으로 이동하겠다는 의미이다. 최신 커밋을 가리키는 HEAD를 A로 리셋한다고 생각하면 된다. 따라서 add 3과 add 4 커밋을 삭제하려면 그 이전 커밋인 add 2 커밋을 최신 커밋으로 만들어야 한다.

add 2 커밋으로 이동하기 위해 git log 명령의 결과 화면에서 add 2 커밋의 커밋 해시를 선택한 후 복사한다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="433" data-origin-height="37"><span data-url="/assets/images/posts/a7172e0f5fcfd70e6d31e5f4bb30e57e24e1f8bd.png" data-phocus="/assets/images/posts/a7172e0f5fcfd70e6d31e5f4bb30e57e24e1f8bd.png"><img src="/assets/images/posts/a7172e0f5fcfd70e6d31e5f4bb30e57e24e1f8bd.png" loading="lazy" width="433" height="37" data-origin-width="433" data-origin-height="37"></span></figure>

이후 git reset 명령 다음에 --hard 옵션까지 입력한 후 붙여 넣어주었다. 그러면 방금 복사해서 붙인 커밋 해시 위치로 HEAD가 옮겨졌다고 나타난다. 즉 방금 복사해서 붙인 커밋이 가장 최신 커밋이 된 것이다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="480" data-origin-height="216"><span data-url="/assets/images/posts/5015be583c34cd9b7eb5f547131c5f3a7568a469.png" data-phocus="/assets/images/posts/5015be583c34cd9b7eb5f547131c5f3a7568a469.png"><img src="/assets/images/posts/5015be583c34cd9b7eb5f547131c5f3a7568a469.png" loading="lazy" width="480" height="216" data-origin-width="480" data-origin-height="216"></span></figure>

git log 명령을 사용해서 로그 목록을 살펴보면 의도한 대로 add 3과 add 4 커밋은 삭제되고 커밋 해시를 복사한 커밋, 즉 add 2 커밋이 최신 커밋이 된 것을 확인할 수 있다. 그럼 rev.txt 파일은 어떻게 되었을까? 파일을 확인해 보면 "1" 다음 "2"까지만 있을 것이다. "3"과 "4"를 추가한 add 3과 add 4가 사라지고 add 2 커밋이 최신 커밋이 되었기 때문에 "2"까지만 남은 것이다.

#### <strong>커밋 변경 이력 취소하기 - git revert</strong>

특정 커밋으로 되돌릴 때 수정한 내용을 삭제해도 된다면 git reset 명령을 사용하면 된다. 하지만 나중을 대비해서 커밋을 취소하더라도 커밋한 기록은 남겨 두어야 할 때가 있다. (인간은 실수할 수도 있기 때문 아닐까..?) 즉, 변경 사항만 취소하고 커밋은 남겨 두는 것이다. 이럴 경우에는 git revert 명령을 사용한다.

다시 한번 rev.txt 파일을 사용해 실습을 해보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="351" data-origin-height="61"><span data-url="/assets/images/posts/badde3c45203aedd05231650ae6d380d11173810.png" data-phocus="/assets/images/posts/badde3c45203aedd05231650ae6d380d11173810.png"><img src="/assets/images/posts/badde3c45203aedd05231650ae6d380d11173810.png" loading="lazy" width="351" height="61" data-origin-width="351" data-origin-height="61"></span></figure>

현재 이 파일에는 1과 2가 있을 것이다. 이 파일을 한 번 더 수정해서 숫자 '7'을 추가해 주자. 수정한 rev.txt를 add 5라는 메시지와 함께 git commit -am 명령을 사용해 커밋해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="477" data-origin-height="322"><span data-url="/assets/images/posts/0feb031643ff0ae1c5f850e6ff5f4d19989b6e00.png" data-phocus="/assets/images/posts/0feb031643ff0ae1c5f850e6ff5f4d19989b6e00.png"><img src="/assets/images/posts/0feb031643ff0ae1c5f850e6ff5f4d19989b6e00.png" loading="lazy" width="477" height="322" data-origin-width="477" data-origin-height="322"></span></figure>

이후 git log를 입력해 버전을 확인해 보면 3개의 버전이 만들어진 것을 확인할 수 있다.

이제 가장 최근에 커밋한 add 5 버전을 취소하고, add 5 직전 커밋인 add 2로 되돌아가려고 한다. 또한 여기에서는 취소하는 add 5 버전을 삭제하지 않고 남겨 두려고 한다. 이럴 때는 revert 명령을 사용하고 바로 뒤에 취소할  버전, 즉 add 5의 커밋 해시를 지정한다.

> git revert \[커밋 해시\]
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="389" data-origin-height="44"><span data-url="/assets/images/posts/c9adde929566edb8ec2b8d82264811afd912d5dd.png" data-phocus="/assets/images/posts/c9adde929566edb8ec2b8d82264811afd912d5dd.png"><img src="/assets/images/posts/c9adde929566edb8ec2b8d82264811afd912d5dd.png" loading="lazy" width="389" height="44" data-origin-width="389" data-origin-height="44"></span></figure>

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="617" data-origin-height="246"><span data-url="/assets/images/posts/de58fb24adaa491726b9daf150a6bf26f5d48759.png" data-phocus="/assets/images/posts/de58fb24adaa491726b9daf150a6bf26f5d48759.png"><img src="/assets/images/posts/de58fb24adaa491726b9daf150a6bf26f5d48759.png" loading="lazy" width="617" height="246" data-origin-width="617" data-origin-height="246"></span></figure>

git revert 명령을 사용하면 기본 편집기가 자동으로 나타나면서 커밋 메시지를 입력할 수 있다. 커밋 메시지 맨 위에 add 5 버전을 revert 했다는 메시지가 나타난다. 커밋을 취소하면서 남겨 둘 내용이 있다면 문서 맨 위에 입력하고 저장한다. 확인이 끝나면 창을 닫아주면 된다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="474" data-origin-height="352"><span data-url="/assets/images/posts/69da6a160b50a780fa75702dbfa8214599c62c8e.png" data-phocus="/assets/images/posts/69da6a160b50a780fa75702dbfa8214599c62c8e.png"><img src="/assets/images/posts/69da6a160b50a780fa75702dbfa8214599c62c8e.png" loading="lazy" width="474" height="352" data-origin-width="474" data-origin-height="352"></span></figure>

실제로 버전이 어떻게 바뀌었는지 확인하기 위해 git log 명령을 입력했더니 로그에 add 5를 revert 한 새로운 커밋이 생긴 것을 확인할 수 있다. 그리고 원하던 기존 add 5 역시 사라지지 않았다. add 5 버전을 지우는 대신 add 5에서 변경한 내용만 취소하고, add 5를 취소했다는 커밋을 새로 만든 것이다. rev.txt 내용을 보면 add 5 커밋에서 추가한 7이 취소된 것을 확인할 수 있다.
