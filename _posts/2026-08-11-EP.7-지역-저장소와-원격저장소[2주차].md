### <strong>#지역 저장소를 원격 저장소에 연결하기</strong>

원격 저장소를 만들어봤으니 이제 지역 저장소와 연결하는 방법에 대해 알아보겠다.

#### <strong>지역 저장소 만들기</strong>

먼저 깃 허브의 권격 저장소에 연결할 새로운 지역 저장소를 만들겠다. 이름은 spact-git이라는 새로운 디렉터리를 만들어 VS Code에 작업 폴더로 추가해 주었다. 이후 git init 명령을 입력해 지역 저장소로 만들어 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="672" data-origin-height="184"><span data-url="/assets/images/posts/e7e751221d56a5ddfc70e8c2826b744c6688a795.png" data-phocus="/assets/images/posts/e7e751221d56a5ddfc70e8c2826b744c6688a795.png"><img src="/assets/images/posts/e7e751221d56a5ddfc70e8c2826b744c6688a795.png" loading="lazy" width="672" height="184" data-origin-width="672" data-origin-height="184"></span></figure>

이제 지역 저장소에 커밋을 만들어보겠다. 새 파일을 하나 만드는데 파일 이름은 f1.txt라고 하겠다. 파일 내용은 'spact'라고 적어 주고 저장해 주었다. 다음으로 f1.txt를 스테이지에 올린 후 커밋해 주었다. 커밋 메시지는 'add spact'라고 하겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="444" data-origin-height="116"><span data-url="/assets/images/posts/7bc626cb98e56ddf994799b913634fd10eef2366.png" data-phocus="/assets/images/posts/7bc626cb98e56ddf994799b913634fd10eef2366.png"><img src="/assets/images/posts/7bc626cb98e56ddf994799b913634fd10eef2366.png" loading="lazy" width="444" height="116" data-origin-width="444" data-origin-height="116"></span></figure>

git log 명령으로 커밋이 잘 되었는지 확인해 주었다.

#### <strong>원격 저장소에 연결하기</strong>

깃허브에 저장소를 만들면 첫 화면에 원격 저장소에 접속하는 여러 가지 방법을 알려준다. 그중 '...or push an existing repository from the command line' (커맨드 라인에서 기존 저장소를 푸시하기) 방법을 사용해서 지역 저장소에 있는 파일을 원격 저장소로 올려보겠다.

> git remote add origin \[주소\]
{: data-ke-style="style3"}

지역 저장소와 권격 저장소를 연결하려면 우선 원격 저장소의 HTTPS 주소를 알아야 한다.  지역 저장소와 연결할 저장소를 선택하고 깃허브 주소를 복사한다. 터미널 창에 위와 같이 입력해 주면 된다. 이 명령은 원격 저장소(remote)에 origin을 추가(add)하겠다고 깃에게 알려주는 것이다. 여기에서 origin은 깃허브 저장수 주소를 가리킨다. 깃허브 저장소 주소를 그대로 쓰면 너무 길기 때문에 origin이라는 단어로 줄여서 remote에 추가하는 것이다.

> git remote -v
{: data-ke-style="style3"}

오류 메시지 없이 프롬프트($)가 나타나면 제대로 연결된 것이다. 원격 저장소에(remote)에 제대로 연결됐는지 확인해 보자. git remote 명령에 -v 옵션을 붙여서 입력하면 된다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="425" data-origin-height="68"><span data-url="/assets/images/posts/bd697c2252bfeff356c8a3e3225ee2ac8560cf7c.png" data-phocus="/assets/images/posts/bd697c2252bfeff356c8a3e3225ee2ac8560cf7c.png"><img src="/assets/images/posts/bd697c2252bfeff356c8a3e3225ee2ac8560cf7c.png" loading="lazy" width="425" height="68" data-origin-width="425" data-origin-height="68"></span></figure>

다음과 같이 remote에 origin이 연결되어 있고, origin이 가리키는 주소가 바로 옆에 표시된다.

### <strong>#지역 저장소와 원격 저장소 동기화하기</strong>

지역 저장소와 원격 저장소를 연결했으니 이제부터 지역 저장소의 소스를 원격 저장소에 올릴 수도 있고, 반대로 원격 저장소에 있는 소스를 지역 저장소로 내려받을 수도 있다.

#### <strong>원격 저장소에 커밋 올리기</strong>

지역 저장소의 커밋을 원격 저장소로 보내는 푸시 방법을 알아보자. 

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="873" data-origin-height="130"><span data-url="/assets/images/posts/c176f7aa6761bbee72360a0e45d202be6c8b9ae7.png" data-phocus="/assets/images/posts/c176f7aa6761bbee72360a0e45d202be6c8b9ae7.png"><img src="/assets/images/posts/c176f7aa6761bbee72360a0e45d202be6c8b9ae7.png" loading="lazy" width="873" height="130" data-origin-width="873" data-origin-height="130"></span></figure>

원격 저장소에 처음 접속할 때 나타나는 내용 가운데 두 번째, 세 번째 항목이 푸시하는 방법이다.

> git push -u origin main
{: data-ke-style="style3"}

이제 다시 VS Code로 돌아가보자. 터미널 창에 위와 같이 입력해 준다. 지역 저장소의 브랜치를 origin(원격 저장소)의 main 브랜치로 푸시하라는 명령이다. 여기에서 -u 옵션은 지역 저장소의 브랜치를 원격 저장소의 브랜치에 연결하는 것으로 처음에 한 번만 사용하면 된다. 이후에는 -u 옵션이나 main 브랜치 이름 없이 푸시할 수 있다.

<figure class="imagegridblock"><div class="image-container"><span data-url="/assets/images/posts/77f938f629b3f820ae0b3eaa7afa58a93e61c51d.png" data-phocus="/assets/images/posts/77f938f629b3f820ae0b3eaa7afa58a93e61c51d.png" data-origin-width="400" data-origin-height="350" data-is-animation="false" data-widthpercent="33.4" style="width: 33.0128%; margin-right: 10px;"><img src="/assets/images/posts/77f938f629b3f820ae0b3eaa7afa58a93e61c51d.png" loading="lazy" width="400" height="350"></span><span data-url="/assets/images/posts/ec69867bd2a7c49fc6318a08ccd8ae5b2af859ad.png" data-phocus="/assets/images/posts/ec69867bd2a7c49fc6318a08ccd8ae5b2af859ad.png" data-origin-width="654" data-origin-height="287" data-is-animation="false" style="width: 65.8244%;" data-widthpercent="66.6"><img src="/assets/images/posts/ec69867bd2a7c49fc6318a08ccd8ae5b2af859ad.png" loading="lazy" width="654" height="287"></span></div></figure>

sign in with your browser 버튼을 눌러 로그인 및 인증을 해준다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="441" data-origin-height="160"><span data-url="/assets/images/posts/556dded3f41cd98259a4cad204256f87f59d585e.png" data-phocus="/assets/images/posts/556dded3f41cd98259a4cad204256f87f59d585e.png"><img src="/assets/images/posts/556dded3f41cd98259a4cad204256f87f59d585e.png" loading="lazy" width="441" height="160" data-origin-width="441" data-origin-height="160"></span></figure>

사용자 인증이 끝나는 동시에 터미널 창에서 푸시가 진행된다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="934" data-origin-height="578"><span data-url="/assets/images/posts/2ab2966532ba4d69b0580d8aa9c9579f4e401b5b.png" data-phocus="/assets/images/posts/2ab2966532ba4d69b0580d8aa9c9579f4e401b5b.png"><img src="/assets/images/posts/2ab2966532ba4d69b0580d8aa9c9579f4e401b5b.png" loading="lazy" width="934" height="578" data-origin-width="934" data-origin-height="578"></span></figure>

푸시가 끝나면 지역 저장소의 커밋이 원격 저장소로 올라간다. 푸시가 끝나고 깃허브 저장소 웹 브라우저로 가보면 지역 저장소에 있던 f1.txt 파일이 원격 저장소에 올라와 있을 것이다. 저장소의 파일 목록에는 파일 이름과 함께 커밋 메시지도 나타난다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="515" data-origin-height="225"><span data-url="/assets/images/posts/354cd1cd098fabd6367774e8475d00b0fc592b53.png" data-phocus="/assets/images/posts/354cd1cd098fabd6367774e8475d00b0fc592b53.png"><img src="/assets/images/posts/354cd1cd098fabd6367774e8475d00b0fc592b53.png" loading="lazy" width="515" height="225" data-origin-width="515" data-origin-height="225"></span></figure>

파일 위 시계모양 버튼을 누르면 커밋한 날짜와 사람, 메시지 등을 볼 수 있다.

#### <strong>원격 저장소에 파일 올리기 - git push</strong>

지역 저장소와 원격 저장소를 연결해서 한 번이라도 푸시했다면 그다음부터는 더 간단하게 푸시할 수 있다.

> git commit -am "add Doit!"
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="378" data-origin-height="67"><span data-url="/assets/images/posts/67db59ddd9c2f1eb3f3a359ad3488ab6c85438aa.png" data-phocus="/assets/images/posts/67db59ddd9c2f1eb3f3a359ad3488ab6c85438aa.png"><img src="/assets/images/posts/67db59ddd9c2f1eb3f3a359ad3488ab6c85438aa.png" loading="lazy" width="378" height="67" data-origin-width="378" data-origin-height="67"></span></figure>

지역 저장소에 또 다른 커밋을 만들고 푸시해 보겠다. f1.txt 파일에 원래 내용 다음 줄에 'Do it!'를 추가하고 저장한다. 'add Doit!'라는 커밋 메시지를 사용해 커밋한다.

> git push
{: data-ke-style="style3"}

지역 저장소에 새로운 커밋이 만들어졌으니 원격 저장소로 푸시해 보자. 이미 원격 저장소에 푸시하면서 사용자 인증을 했기 때문에 git push만 입력해 주면 된다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="454" data-origin-height="130"><span data-url="/assets/images/posts/5ff5bd1438cd1c4788df2644979d5cce03348361.png" data-phocus="/assets/images/posts/5ff5bd1438cd1c4788df2644979d5cce03348361.png"><img src="/assets/images/posts/5ff5bd1438cd1c4788df2644979d5cce03348361.png" loading="lazy" width="454" height="130" data-origin-width="454" data-origin-height="130"></span></figure>

방금 만든 커밋이 깃허브의 원격 저장소로 푸시되었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="680" data-origin-height="114"><span data-url="/assets/images/posts/a4a0cfd7efaeb889cd71bb30b54ca883e1d9c8ca.png" data-phocus="/assets/images/posts/a4a0cfd7efaeb889cd71bb30b54ca883e1d9c8ca.png"><img src="/assets/images/posts/a4a0cfd7efaeb889cd71bb30b54ca883e1d9c8ca.png" loading="lazy" width="680" height="114" data-origin-width="680" data-origin-height="114"></span></figure>

깃허브 저장소 화면을 다시 확인해 보면 파일 이름 오른쪽에 최신 커밋 메시지 'add Doit!'가 보이고, 파일 목록 위를 보면 1Commits이었던 것이 2Commits로 바뀌었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="933" data-origin-height="571"><span data-url="/assets/images/posts/3051f38ace831cf33fff48166addb035528e7a0c.png" data-phocus="/assets/images/posts/3051f38ace831cf33fff48166addb035528e7a0c.png"><img src="/assets/images/posts/3051f38ace831cf33fff48166addb035528e7a0c.png" loading="lazy" width="933" height="571" data-origin-width="933" data-origin-height="571"></span></figure>

2Commits을 눌러보면 조금 전에 푸시한 커밋이 올라온 것을 볼 수 있다. 어떤 걸 변경했는지 궁금하다면 커밋 이름 오른쪽에 있는 커밋 해시를 클릭해 보면 파일에서 삭제한 것은 붉은색, 추가한 것은 초록색을 표시되어 파일에서 어느 부분이 바뀌었는지 알 수 있다.

#### <strong>원격 저장소에서 직접 커밋하기</strong>

원격 저장소에 커밋을 만들면 지역 저장소에 없으므로 가져와야 한다. 이번에는 깃허브에서 파일을 직접 수정해서 원격 저장소에 새로운 커밋을 만들어 보겠다.

앞에서 커밋을 푸시한 원격 저장소로 접속한다. 이미 푸시한 f1.txt 파일이 있다. 여기에 새로운 파일을 추가해 보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="930" data-origin-height="586"><span data-url="/assets/images/posts/b6f0d10ef444e6510c19dd58c60ceff375f1c599.png" data-phocus="/assets/images/posts/b6f0d10ef444e6510c19dd58c60ceff375f1c599.png"><img src="/assets/images/posts/b6f0d10ef444e6510c19dd58c60ceff375f1c599.png" loading="lazy" width="930" height="586" data-origin-width="930" data-origin-height="586"></span></figure>

파일 목록 위에 는 + 버튼을 클릭한 후 Create new file을 선택한다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="932" data-origin-height="364"><span data-url="/assets/images/posts/6cef851c768c0de0398ae918dfaba6512bd03670.png" data-phocus="/assets/images/posts/6cef851c768c0de0398ae918dfaba6512bd03670.png"><img src="/assets/images/posts/6cef851c768c0de0398ae918dfaba6512bd03670.png" loading="lazy" width="932" height="364" data-origin-width="932" data-origin-height="364"></span></figure>

맨 위에 파일이름은 f2.txt로 해주었고, 내용에는 "여름방학 모각공!"이라고 입력해 주었다. 내용까지 입력이 끝났다면 Commit changes... 를 클릭해 준다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="941" data-origin-height="648"><span data-url="/assets/images/posts/befa3c833d385ecd313905cef5c5f708af3e66b6.png" data-phocus="/assets/images/posts/befa3c833d385ecd313905cef5c5f708af3e66b6.png"><img src="/assets/images/posts/befa3c833d385ecd313905cef5c5f708af3e66b6.png" loading="lazy" width="941" height="648" data-origin-width="941" data-origin-height="648"></span></figure>

커밋 메시지와 설명들을 원하는 내용으로 수정한 후 commit changes를 클릭해 준다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="667" data-origin-height="213"><span data-url="/assets/images/posts/eb55d77574e34947ffce8fee56f06f2fb2b7595e.png" data-phocus="/assets/images/posts/eb55d77574e34947ffce8fee56f06f2fb2b7595e.png"><img src="/assets/images/posts/eb55d77574e34947ffce8fee56f06f2fb2b7595e.png" loading="lazy" width="667" height="213" data-origin-width="667" data-origin-height="213"></span></figure>

원격 저장소에 새로운 커밋이 추가되었다.

#### <strong>원격 저장소에서 커밋 내려받기 - git pull</strong>

원격 저장소에서 직접 커밋하면 지역 저장소와 버전 차이가 생긴다. 이럴 때는 원격 저장소와 지역 저장소의 상태가 같아지도록 원격 저장소의 커밋을 지역 저장소로 가져온다. 이것을 풀한다(pull)고 한다. 지금부터 깃허브에서 풀하는 방법을 알아보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="684" data-origin-height="267"><span data-url="/assets/images/posts/9a337e8b6a3d6be6205787d935fbea28e93221af.png" data-phocus="/assets/images/posts/9a337e8b6a3d6be6205787d935fbea28e93221af.png"><img src="/assets/images/posts/9a337e8b6a3d6be6205787d935fbea28e93221af.png" loading="lazy" width="684" height="267" data-origin-width="684" data-origin-height="267"></span></figure>

깃허브 사이트에서 f2.txt라는 파일을 새로 만들었지만 spact-git 지역 저장소에는 f2.txt 파일이 없다.

> git pull origin main
{: data-ke-style="style3"}

원격 저장소에서 커밋을 풀할 때는 git pull 명령을 사용한다. 그리고 그 뒤에 원격 저장소 이름과 지역 저장소의 브랜치 이름을 넣어 준다. 여기에서는 origin(원격 저장소)을 지역 저장소의 main 브랜치로 가져오라고 하겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="548" data-origin-height="253"><span data-url="/assets/images/posts/b39cee39d46222436e8f8791b6759a42c856f26b.png" data-phocus="/assets/images/posts/b39cee39d46222436e8f8791b6759a42c856f26b.png"><img src="/assets/images/posts/b39cee39d46222436e8f8791b6759a42c856f26b.png" loading="lazy" width="548" height="253" data-origin-width="548" data-origin-height="253"></span></figure>

원격 저장소에서 소스 파일을 가져오는 과정이 화면에 나타난다. 가져오기가 끝나면 f2.txt가 보일 것이다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="538" data-origin-height="354"><span data-url="/assets/images/posts/749aafe5bb2a0324ebcfcec44599736885559cab.png" data-phocus="/assets/images/posts/749aafe5bb2a0324ebcfcec44599736885559cab.png"><img src="/assets/images/posts/749aafe5bb2a0324ebcfcec44599736885559cab.png" loading="lazy" width="538" height="354" data-origin-width="538" data-origin-height="354"></span></figure>

git log 명령을 커밋 로그를 확인해 보니 깃허브 사이트에서 만들었던 커밋이 지역 저장소 커밋 로그에도 나타나는 것을 확인할 수 있다. 그리고 커밋 해시 오른쪽을 보면 (HEAD -&gt; main, origin/main)라고 되어있다. origin/main가 추가된 것을 확인할 수 있는데 원격 저장소의 최신 커밋이라는 뜻이다.
