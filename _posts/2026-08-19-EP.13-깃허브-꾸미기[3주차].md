이제 깃허브에서 자신의 개발 이력을 드러낼 수 있는 프로필 관리 방법을 알아보겠다.

### <strong>#깃허브 프로필 관리하기</strong>

#### <strong>프로필 둘러보기</strong>

깃허브에서 다른 사람의 저장소를 살펴보다가 흥미로운 소스를 발견한다면 먼저 작성한 사람이 어떤 사람인지 궁금해질 때가 있다. 이처럼 깃허브 프로필은 내용을 보고 협업이나 일자리 제안을 받을 수도 있으므로 개발자로서 자신의 개발 경력을 드러낼 수 있는 손쉬운 방법이기도 하다.

#### <strong>프로필 작성하기</strong>

깃허브 저장소는 대부분 공개되어 있으므로 누구나 찾아와서 볼 수 있다. 

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="1479" data-origin-height="607"><span data-url="/assets/images/posts/3b71310c93cda45183d7786e0c4cab43402b0e9b.png" data-phocus="/assets/images/posts/3b71310c93cda45183d7786e0c4cab43402b0e9b.png"><img src="/assets/images/posts/3b71310c93cda45183d7786e0c4cab43402b0e9b.png" loading="lazy" width="1479" height="607" data-origin-width="1479" data-origin-height="607"></span></figure>

'https://github.com/아이디'로 접속하면 해당 아이디 사용자의 프로필 사진을 비롯해 저장소 목록과 커밋 현황 등 다양한 정보를 보여 주는 화면이 나타난다. 화면 왼쪽 위에 있는 프로필 사진을 클릭해 준다. 그럼 설정창이 뜨는데 공개할 사용자 정보 및 프로필을 추가로 입력하고 Update pofile을 클릭한다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="1394" data-origin-height="692"><span data-url="/assets/images/posts/d3c44cbd623b5bc629e901585d51f02b49b34f59.png" data-phocus="/assets/images/posts/d3c44cbd623b5bc629e901585d51f02b49b34f59.png"><img src="/assets/images/posts/d3c44cbd623b5bc629e901585d51f02b49b34f59.png" loading="lazy" width="1394" height="692" data-origin-width="1394" data-origin-height="692"></span></figure>

프로필 화면 왼쪽에 지금까지 작성한 정보가 나타난다. 이제 다른 사용자가 자신의 저장소에 방문했을 때 프로필 화면에서 내가 누구인지 알 수 있을 것이다.

#### <strong>컨트리뷰션 살펴보기</strong>

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="777" data-origin-height="227"><span data-url="/assets/images/posts/0b9dff1b3dee70036a8c21d58ceb39f5c63e5996.png" data-phocus="/assets/images/posts/0b9dff1b3dee70036a8c21d58ceb39f5c63e5996.png"><img src="/assets/images/posts/0b9dff1b3dee70036a8c21d58ceb39f5c63e5996.png" loading="lazy" width="777" height="227" data-origin-width="777" data-origin-height="227"></span></figure>

깃허브에서 컨트리뷰션(contribution)이란 자신의 깃허브에 커밋을 올리는 것뿐만 아니라, 다른 오픈 소스 프로젝트에 PR을 등록하는 것처럼 깃허브에서 하는 모든 활동을 가리킨다. 깃허브 프로필 화면에서 초록색 사각형이 찍힌 부분을 컨트리뷰션 그래프(contribution graph)라고 한다. 이 그래프를 보면 사용자가 깃허브에서 1년 동안 얼마나 활발하게 활동했는지 알 수 있다.

작은 사각형 하나가 하루에 해당하고, 컨트리뷰션이 잇는 날에는 사각형에 초록색이 칠해진다. 초록색이 진할수록 그날 컨트리뷰션이 많았다는 뜻이다. 사격형 이로 마우스 포인터를 올리면 날짜와 컨트리뷰션 개수가 나타나고, 사각형을 클릭하면 그래프 아래에 선택한 날짜의 컨트리뷰션 활동이 나열된다. 이렇게 컨트리뷰션 그래프에서는 사용자의 활동 내역이 한눈에 보이므로 이력서 역할을 한다고 책에서 이야기하고 있다. 컨트리뷰션에는 개인이 작성한 소스 코드를 커밋하거나 오픈소스 프로젝트에 기여하는 커밋 모두 포함된다.

### <strong>#README 파일 작성하면서 마크다운 익히기</strong>

공개된 깃허브 저장소는 전 세계 누구나 구경할 수 있어서 활동할수록 방문하는 사람이 늘어날 것이다. 하지만 프로필과 컨트리뷰션 그래프만 살펴보는 것으로는 그 저장소가 어떤 곳인지 구체적으로 알기 어렵다. 그래서 이제부터 안내문 역할을 하는 README 파일이 있다. 이제부터 README 파일을 작성하는 방법을 알아보겠다.

#### <strong>README 파일은 어떤 용도로 사용할까?</strong>

README 파일을 작성하기 전에 다른 저장소에서는 README 파일을 어떻게 사용하는지 살펴보자. README 파일은 마크다운(markdown) 문법을 사용하므로 확장자는 .md를 사용한다.

깃허브 저장소의 README 파일은 해당 저장소를 소개하는 공간이다. 예를 들어 VS Code 편집기의 공식 깃허브 저장소를 한번 살펴보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="983" data-origin-height="614"><span data-url="/assets/images/posts/7e8a9dbfa527c2305d929f838d8d4618cf408a00.png" data-phocus="/assets/images/posts/7e8a9dbfa527c2305d929f838d8d4618cf408a00.png" data-alt="https://github.com/microsoft/vscode-docs"><img src="/assets/images/posts/7e8a9dbfa527c2305d929f838d8d4618cf408a00.png" loading="lazy" width="983" height="614" data-origin-width="983" data-origin-height="614"></span><figcaption>https://github.com/microsoft/vscode-docs</figcaption></figure>

접속해 보면 README에서 VS Code와 관련한 내용을 제공하고 있다.

#### <strong>README 파일 작성하기</strong>

README 파일은 처음에 저장소를 만들 때 저장소 이름을 입력하고 Add a README file에 체크하면 자동으로 만들 수 있다. 하지만 README 파일은 처음부터 만들지 않더라도 저장소에서 필요할 때 추가할 수도 있다. 한번 미리 만들어 놓은 저장소에 새로 README 파일을 추가하는 방법을 살펴보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="1303" data-origin-height="637"><span data-url="/assets/images/posts/0f0593145108d5034289574036d2bda7e352d20e.png" data-phocus="/assets/images/posts/0f0593145108d5034289574036d2bda7e352d20e.png"><img src="/assets/images/posts/0f0593145108d5034289574036d2bda7e352d20e.png" loading="lazy" width="1303" height="637" data-origin-width="1303" data-origin-height="637"></span></figure>

먼저 README 파일을 만들 깃허브의 저장소로 접속해 준다. 나는 이전에 만들어 놓은 Doit-study라는 저장소를 사용하겠다. 파일 목록 아래에 있는 Add a README를 클릭하면 README 새 파일을 만들 수 있다.

<figure class="imagegridblock"><div class="image-container"><span data-url="/assets/images/posts/1585ab91b79fec6552fb89656c9d2b2f42d4d813.png" data-phocus="/assets/images/posts/1585ab91b79fec6552fb89656c9d2b2f42d4d813.png" data-origin-width="900" data-origin-height="308" data-is-animation="false" style="width: 53.3467%; margin-right: 10px;" data-widthpercent="53.97"><img src="/assets/images/posts/1585ab91b79fec6552fb89656c9d2b2f42d4d813.png" loading="lazy" width="900" height="308"></span><span data-url="/assets/images/posts/7f24b36e90623fbcfc52a88e84e7c3b0521797f0.png" data-phocus="/assets/images/posts/7f24b36e90623fbcfc52a88e84e7c3b0521797f0.png" data-origin-width="907" data-origin-height="364" data-is-animation="false" style="width: 45.4906%;" data-widthpercent="46.03"><img src="/assets/images/posts/7f24b36e90623fbcfc52a88e84e7c3b0521797f0.png" loading="lazy" width="907" height="364"></span></div></figure>

텍스트 편집기에 원하는 내용을 입력해 준다. 이때 Enter를 두 번 눌러 가운데 빈 줄을 하나 넣어야 실제 화면에서 줄이 바뀌어 나타난다. 또한 README 파일 작성 화면에는 Edit 탭과 Preview 탭이 잇다. Edit 탭에서 내용을 작성하고 Preview 탭을 클릭해 보면 결과 화면을 미리 볼 수 있다. 작성이 마무리가 되었다면 상단에 Commit changes...를 클릭해 준다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="480" data-origin-height="600"><span data-url="/assets/images/posts/fbadec32ccd7dee8bb69d75bf7ade6cc890672e6.png" data-phocus="/assets/images/posts/fbadec32ccd7dee8bb69d75bf7ade6cc890672e6.png"><img src="/assets/images/posts/fbadec32ccd7dee8bb69d75bf7ade6cc890672e6.png" loading="lazy" width="480" height="600" data-origin-width="480" data-origin-height="600"></span></figure>

README 파일을 작성하거나 수정하는 것도 하나의 커밋이 되겠다. README 파일을 저장소에 저장하려면 커밋해야 한다. 커밋할 때는 README 작성 화면 아래쪽에서 커밋 메시지를 작성하면 되는데, 기본으로 적힌 커밋 메시지를 그대로 사용할 수도 있고 직접 입력할 수도 있다. 작성을 끝내고 Commit changes을 클릭해 커밋해 준다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="675" data-origin-height="603"><span data-url="/assets/images/posts/ba8e70067769ab13bc6548462e6bc70d7677e711.png" data-phocus="/assets/images/posts/ba8e70067769ab13bc6548462e6bc70d7677e711.png"><img src="/assets/images/posts/ba8e70067769ab13bc6548462e6bc70d7677e711.png" loading="lazy" width="675" height="603" data-origin-width="675" data-origin-height="603"></span></figure>

커밋이 추가되면서 자동으로 저장소 첫 화면으로 돌아온다. 파일 목록에는 방금 추가한 README.md 파일이 보이고, 아래에는 작성한 README 파일의 내용이 나타날 것이다.
