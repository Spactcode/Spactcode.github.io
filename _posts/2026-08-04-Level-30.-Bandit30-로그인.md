오늘은 Bandit30 문제를 해결해보려고 한다.

이번 문제도 역시나 지난번 문제 정보와 동일하게 제시되어 있다.

그럼 지난번 문제처럼 git clone을 통해 파일을 다운로드 받아서 문제를 풀어나가면 되겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="966" data-origin-height="383"><span data-url="/assets/images/posts/faf4bc6b4d975f288315b5a0fb490295e442f980.png" data-phocus="/assets/images/posts/faf4bc6b4d975f288315b5a0fb490295e442f980.png"><img src="/assets/images/posts/faf4bc6b4d975f288315b5a0fb490295e442f980.png" loading="lazy" width="966" height="383" data-origin-width="966" data-origin-height="383"></span></figure>

이번에도 bandit 디렉터리에 파일을 다운받아줬다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="479" data-origin-height="262"><span data-url="/assets/images/posts/c322945bc921601444221a96911590de18699d78.png" data-phocus="/assets/images/posts/c322945bc921601444221a96911590de18699d78.png"><img src="/assets/images/posts/c322945bc921601444221a96911590de18699d78.png" loading="lazy" width="479" height="262" data-origin-width="479" data-origin-height="262"></span></figure>

이후 ls명령어로 다운로드하여 준 파일을 확인하면 지난번과 같은 repo라는 디렉터리가 다운로드된 것을 확인할 수 있다. repo 디렉터리로 가서 어떤 파일들이 있나 확인해 보면 README.md라는 파일이 있는 것을 확인하였다. 이 파일을 읽어보면 username은 bandit30이고, password는 &lt;no passwords in production!&gt;로 productio에서는 비밀번호가 없다며 알려주지 않는 상태이다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="846" data-origin-height="227"><span data-url="/assets/images/posts/0ba3933732ff1c51d88d06bb1d3f2b40b7317c02.png" data-phocus="/assets/images/posts/0ba3933732ff1c51d88d06bb1d3f2b40b7317c02.png"><img src="/assets/images/posts/0ba3933732ff1c51d88d06bb1d3f2b40b7317c02.png" loading="lazy" width="846" height="227" data-origin-width="846" data-origin-height="227"></span></figure>

그래서 지난번 문제를 해결할 때처럼 git log를 사용해 보았다. 살펴보니 2가지 버전이 있는데 하나는 username을 고치는 것과 하나는 README.md를 처음 commit 한 버전이 있는 것을 확인하였다. 그럼 한번 username을 고치기 이전으로 가봐도 좋을 것 같다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="400" data-origin-height="154"><span data-url="/assets/images/posts/c4d09b3b44ba95969746092b02ecaec928c3893f.png" data-phocus="/assets/images/posts/c4d09b3b44ba95969746092b02ecaec928c3893f.png"><img src="/assets/images/posts/c4d09b3b44ba95969746092b02ecaec928c3893f.png" loading="lazy" width="400" height="154" data-origin-width="400" data-origin-height="154"></span></figure>

git checkout 명령어로 버전을 바꿔준 뒤 다시 README.md 파일을 살펴보면 정말 username만 변경된 것을 확인할 수 있다.

그래도 branch에 대해 간단하게 살펴보면, branch를 하나의 길이라고 생각해 보자. 그리고 git에는 main branch가 있다고 가정해 보자. 모든 팀원이 이 branch에 개발도 하고 파일 첨부도 할 것이다. 그런데 이때 팀원 A가 이 main branch에 있는 프로젝트를 참고해서 새로운 프로젝트를 만들 수 있다는 생각이 들었다고 하자. 그래서 새로운 branch인 A branch를 만들었다. 그러면 현재 이 git에는 총 2개의 branch가 생긴 것이다. 그럼 main에서 개발하는 사람은 main에서 그대로 개발을 하고 A에서 개발하는 팀원 A는 A에서 그대로 개발을 병렬적으로 할 수 있는 상황이 된 것이다.

그럼 현재 내가 있는 branch는 어떤 branch인지 알아보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="406" data-origin-height="132"><span data-url="/assets/images/posts/0113df0b8c513fe6404ff4af6b54384d7a7f225c.png" data-phocus="/assets/images/posts/0113df0b8c513fe6404ff4af6b54384d7a7f225c.png"><img src="/assets/images/posts/0113df0b8c513fe6404ff4af6b54384d7a7f225c.png" loading="lazy" width="406" height="132" data-origin-width="406" data-origin-height="132"></span></figure>

git branch -a 명령어를 통해 존재하는 모든 branch를 출력하였다. 현재 총 4개의 branch가 있는 것을 확인하였고, 보통 정보 노출은 개발 버전의 git에서 이루어진다고 한다. 이 4개의 branch 중 개발 버전의 branch는 dev인 것 같다.(보통 개발 버전은 dev를 많이 사용한다고 한다.) 

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="584" data-origin-height="55"><span data-url="/assets/images/posts/9c0593062f2a7f105050ba8bd3b2ae5967457267.png" data-phocus="/assets/images/posts/9c0593062f2a7f105050ba8bd3b2ae5967457267.png"><img src="/assets/images/posts/9c0593062f2a7f105050ba8bd3b2ae5967457267.png" loading="lazy" width="584" height="55" data-origin-width="584" data-origin-height="55"></span></figure>

그럼 dev branch로 이동하기 위해 git checkout 명령어를 사용할 것이다. 이 명령어는 전에 커밋을 이동할 때 사용했는데 branch를 전환할 때도 사용할 수 있다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="426" data-origin-height="157"><span data-url="/assets/images/posts/750c6b0c009505d36fcb864c8d2a9f816049e706.png" data-phocus="/assets/images/posts/750c6b0c009505d36fcb864c8d2a9f816049e706.png"><img src="/assets/images/posts/750c6b0c009505d36fcb864c8d2a9f816049e706.png" loading="lazy" width="426" height="157" data-origin-width="426" data-origin-height="157"></span></figure>

branch전환 이후에 cat 명령어로 다시 README.md 파일을 읽어보면 비밀번호를 획득할 수 있다. 예상한 대로 dev가 개발버전의 branch인 것 같다. 이렇게 이번 문제도 끝이 났다.
