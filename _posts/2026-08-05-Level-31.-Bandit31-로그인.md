이번에도 역시나 Git과 관련된 문제이다. 언제나 그랬듯이 bandit 디렉터리에 git clone 명령어로 다운로드하고 시작하겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="965" data-origin-height="462"><span data-url="/assets/images/posts/6030fd40b736c60f77be50dd8c686c1048a5b59e.png" data-phocus="/assets/images/posts/6030fd40b736c60f77be50dd8c686c1048a5b59e.png"><img src="/assets/images/posts/6030fd40b736c60f77be50dd8c686c1048a5b59e.png" loading="lazy" width="965" height="462" data-origin-width="965" data-origin-height="462"></span></figure>

다운로드를 하니 이번에도 repo라는 디렉터리가 있고 안에 README.md라는 파일이 존재한다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="378" data-origin-height="37"><span data-url="/assets/images/posts/b854cc65fb43adfbb5af433bc059a75fd82c5a79.png" data-phocus="/assets/images/posts/b854cc65fb43adfbb5af433bc059a75fd82c5a79.png"><img src="/assets/images/posts/b854cc65fb43adfbb5af433bc059a75fd82c5a79.png" loading="lazy" width="378" height="37" data-origin-width="378" data-origin-height="37"></span></figure>

한번 README.md파일을 읽어보니.. 이제 bandit이 사용자를 놀리기로 한 것 같다. 이 파일은 그냥 빈 파일이라고 말하고 있다.

그럼 지금 시도해 볼 것은 이전 문제들을 풀면서 시도해 봤던 것을 모두 해보는 것이다. 그럼 차례대로 한번 해보겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="839" data-origin-height="113"><span data-url="/assets/images/posts/bdba2b20fb769c41e4f2a47225740003737d81a1.png" data-phocus="/assets/images/posts/bdba2b20fb769c41e4f2a47225740003737d81a1.png"><img src="/assets/images/posts/bdba2b20fb769c41e4f2a47225740003737d81a1.png" loading="lazy" width="839" height="113" data-origin-width="839" data-origin-height="113"></span></figure>

가장 먼저 log를 확인해 봤다. 하지만 내가 본 파일이 최초의 파일이었다. 그럼 다른 방법을 시도해 보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="404" data-origin-height="74"><span data-url="/assets/images/posts/88a39ad29f2ace3d4246c983a48274e76137e33b.png" data-phocus="/assets/images/posts/88a39ad29f2ace3d4246c983a48274e76137e33b.png"><img src="/assets/images/posts/88a39ad29f2ace3d4246c983a48274e76137e33b.png" loading="lazy" width="404" height="74" data-origin-width="404" data-origin-height="74"></span></figure>

이전 레벨에서 사용했던 branch 확인을 시도해 봤다. 이전 레벨과 달리 개발자 branch가 있는 것도 아니고 딱히 특별한 것이 없어 보인다.

이제 이 문제를 풀기 위해서는 새로운 시도를 해야 한다. Git에는 tag라는 것이 있다. 이 tag는 우리가 들었을 때 떠오르는 그 tag 기능이다. 각 커밋마다 주석? 포스트잇? 메모? 추가해 준다고 생각하면 된다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="327" data-origin-height="38"><span data-url="/assets/images/posts/e99839c23fc8cf081a64d2a02a7cff8344ee9c9a.png" data-phocus="/assets/images/posts/e99839c23fc8cf081a64d2a02a7cff8344ee9c9a.png"><img src="/assets/images/posts/e99839c23fc8cf081a64d2a02a7cff8344ee9c9a.png" loading="lazy" width="327" height="38" data-origin-width="327" data-origin-height="38"></span></figure>

그래서 한번 git tag 명령어로 이 Git에 tag가 존재하는지 확인해 보았다. 이 Git에는 secret이라는 tag가 하나 있다는 것을 발견하였다. 그럼 한번 이 tag를 확인해 보자.

> git show \[tag\]
{: data-ke-style="style3"}

tag를 확인하는 명령어는 위와 같다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="395" data-origin-height="32"><span data-url="/assets/images/posts/19b65eb6542d8995e32993dbcae26305c0e61d85.png" data-phocus="/assets/images/posts/19b65eb6542d8995e32993dbcae26305c0e61d85.png"><img src="/assets/images/posts/19b65eb6542d8995e32993dbcae26305c0e61d85.png" loading="lazy" width="395" height="32" data-origin-width="395" data-origin-height="32"></span></figure>

내가 확인하고 싶은 tag는 secret이므로 git show secret 명령어를 입력하였다. 명령어를 입력하니 원하는 비밀번호가 등장하였다. 이렇게 이번 문제도 끝이 났다.
