### <strong>#브랜치에서 커밋하기</strong>

브랜치를 전환하면 브랜치마다 서로 다른 커밋을 처리할 수 있다. 이번에는 브랜치마다 만들어진 커밋이 서로 어떤 관계가 있는지 확인하는 방법과 브랜치 간의 차이점을 확인하는 방법을 알아보자.

#### <strong>전환한 브랜치에서 커밋하기</strong>

앞에서 spact 브랜치로 전환했으므로, 이제 spact 브랜치에서 새로운 커밋을 만들 수 있다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="525" data-origin-height="132"><span data-url="/assets/images/posts/a6434bd0615dff0b2fb2d53c56e9df63b4990d1e.png" data-phocus="/assets/images/posts/a6434bd0615dff0b2fb2d53c56e9df63b4990d1e.png"><img src="/assets/images/posts/a6434bd0615dff0b2fb2d53c56e9df63b4990d1e.png" loading="lazy" width="525" height="132" data-origin-width="525" data-origin-height="132"></span></figure>

먼저 work.txt 파일에 'spact content 4'라는 텍스트를 추가하고 저장한다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="607" data-origin-height="223"><span data-url="/assets/images/posts/27320fd0af728961ad9d5c800c959cda045164f2.png" data-phocus="/assets/images/posts/27320fd0af728961ad9d5c800c959cda045164f2.png"><img src="/assets/images/posts/27320fd0af728961ad9d5c800c959cda045164f2.png" loading="lazy" width="607" height="223" data-origin-width="607" data-origin-height="223"></span></figure>

work.txt 외에도 spact.txt라는 새로운 파일을 만들었다. spact.txt 문서를 만들고 여기에도 똑같이 "spact content 4"를 입력하고 저장했다.

> git add .  
> git commit -m "spact content 4"
{: data-ke-style="style3"}

수정한 work.txt 파일과 새로 만든 spact.txt 파일을 각각 커밋할 수 도 잇지만, 여기에서는 2개를 묶어서 한꺼번에 커밋해 보겠다. 이럴 때 git add 명령 뒤에 한 칸 띈 후 마침표(.)를 붙이면 현재 저장소에서 수정 내용이 있는 파일을 스테이지에 한꺼번에 올릴 수 있다. 이후 "spact content 4"라는 메시지와 함께 커밋해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="332" data-origin-height="92"><span data-url="/assets/images/posts/ea78e2532e6bacc6b790665ecc583b67de638bcb.png" data-phocus="/assets/images/posts/ea78e2532e6bacc6b790665ecc583b67de638bcb.png"><img src="/assets/images/posts/ea78e2532e6bacc6b790665ecc583b67de638bcb.png" loading="lazy" width="332" height="92" data-origin-width="332" data-origin-height="92"></span></figure>

git log 명령을 통해 커밋이 어떻게 저장되었는지 확인해 보았다. 첫 번째 줄에 (HEAD -&gt; spact)이라고 되어 있으니 현재 spact 브랜치로 전환한 상태이고, spact 브랜치의 최신 커밋이 spact content 4라는 걸 알 수 있다.

#### <strong>브랜치와 커밋의 관계 알아보기</strong>

지금까지 spact 브랜치로 전환 후 커밋도 추가해 주었다. 이 상태에서 브랜치와 커밋은 어떻게 연결되어 있는지 확인해 보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="326" data-origin-height="107"><span data-url="/assets/images/posts/cecbe58746a7cd7cabc7849a224cff6ef3888844.png" data-phocus="/assets/images/posts/cecbe58746a7cd7cabc7849a224cff6ef3888844.png"><img src="/assets/images/posts/cecbe58746a7cd7cabc7849a224cff6ef3888844.png" loading="lazy" width="326" height="107" data-origin-width="326" data-origin-height="107"></span></figure>

git log 명령을 사용할 때 --branches 옵션을 추가하면 브랜치마다 최신 커밋을 한눈에 살펴볼 수 있다. 결과 화면을 보면 커밋 해시마다 오른쪽에 (HEAD -&gt; spact)으로 표시되어 있어 해당 커밋이 어떤 브랜치에서 만들었는지 구별할 수 있다. (HEAD -&gt; spact)이라고 되어 있으니 현재 브랜치는 spact이고, 최신 커밋은 spact content 4이다. main 브랜치의 최신 커밋은 main work4이고, github, doit 브랜치의 최신 커밋은 work3이다.

브랜치와 커밋의 관계를 좀 더 보기 쉽게 그래프 형태로도 표시 가능하다. git log 명령에 --graph 옵션을 추가하면 된다.

> git log --graph
{: data-ke-style="style3"}

나는 책에 나온 예시처럼 git log --oneline --branches --graph 명령을 입력해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="324" data-origin-height="140"><span data-url="/assets/images/posts/f7a7934e7c355387676b1d4115b485de9100e63f.png" data-phocus="/assets/images/posts/f7a7934e7c355387676b1d4115b485de9100e63f.png"><img src="/assets/images/posts/f7a7934e7c355387676b1d4115b485de9100e63f.png" loading="lazy" width="324" height="140" data-origin-width="324" data-origin-height="140"></span></figure>

커밋 내역 왼쪽에 수직 점선 (╎)이 보인다. 이 점선이 커밋과 커밋의 관계를 보여준다. 그래프를 살펴보면 spact 브랜치의 최신 커밋은 spact content 4인데, 점선을 따라 spact content 4 커밋의 부모를 찾아가 보면 work3 커밋을 만나게 된다. 즉 spact 브랜치에서는 work3 커밋 다음에 spact work4 커밋이 만들어졌다는 뜻이다.

main 브랜치도 살펴보자. main 브랜치의 최신 커밋은 main work4이다. 그리고 대각선을 따라가 부모 커밋을 찾아보면 work3 커밋이 있다. spact 브랜치와 main 브랜치의 커밋이 같은 부모 커밋을 가지고 있는 것을 확인할 수 있다. 즉, main 브랜치나 spact 브랜치는 work 3 커밋까지는 같고 그 이후부터 브랜치마다 다른 커밋을 만들었다는 사실을 알 수 있다.

#### <strong>브랜치 간의 차이점 살펴보기</strong>

브랜치마다 커밋이 점점 쌓여 갈수록 브랜치 사이에 어떤 차이가 있는지 일일이 확인하기 어려워진다. 이럴 대는 git log 명령에서 브랜치 이름 사이에 마침표 2개(..)를 넣는 명령으로 브랜치 간의 차이를 쉽게 확인할 수 있다. 브랜치 이름과 마침표 사이에는 공백 없이 입력하며, 마침표 왼쪽에 있는 브랜치를 기준으로 오른쪽 브랜치와 비교한다. 한번 main 브랜치와 spact 브랜치의 차이점이 무엇인지 확인해 보자.

> git log main..spact
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="290" data-origin-height="81"><span data-url="/assets/images/posts/3b6e4a0f8993cafaab7cd82a62aa182be04963ab.png" data-phocus="/assets/images/posts/3b6e4a0f8993cafaab7cd82a62aa182be04963ab.png"><img src="/assets/images/posts/3b6e4a0f8993cafaab7cd82a62aa182be04963ab.png" loading="lazy" width="290" height="81" data-origin-width="290" data-origin-height="81"></span></figure>

git log main..spact 명령을 입력해 주면 main 브랜치는 없고 spact 브랜치에만 있는 커밋을 보여준다.

> git log spact..main
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="408" data-origin-height="114"><span data-url="/assets/images/posts/aa07819ce7cce827ca3e2d1bcdfcd923b48d9b7f.png" data-phocus="/assets/images/posts/aa07819ce7cce827ca3e2d1bcdfcd923b48d9b7f.png"><img src="/assets/images/posts/aa07819ce7cce827ca3e2d1bcdfcd923b48d9b7f.png" loading="lazy" width="408" height="114" data-origin-width="408" data-origin-height="114"></span></figure>

반대로 spact 브랜치를 기준으로 main 브랜치와 비교하면, spact 브랜치에는 없고 main 브랜치에만 있는 커밋을 보여준다.

### <strong>#브랜치 병합하기</strong>

브랜치마다 각각 커밋할 수 있더라도 어는 시점에서는 브랜치 작업을 마무리하고 기존 브랜치와 합쳐야 한다. 이번에는 병합하는 방법과 병합하면서 브랜치 끼리 충돌할 때 해결하는 방법에 대해 공부해 보자.

#### <strong>서로 다른 파일 병합하기</strong>

브랜치 간에 서로 다른 파일을 가지고 있을 때 브랜치를 병합하는 방법을 알아보자. 브랜치 병합 실습을 위해 새로운 저장소를 만들어서 진행해 보겠다.

기존 작업하던 폴더는 닫아주고 새로운 merge라는 디렉터리를 만들고 작업 폴더로 추가해 주었다. 이후 git init 명령어를 통해 현재 작업 폴더를 깃 저장소로 만들어주었다. 다음으로 work.txt 파일을 만든 후 '1'을 입력하고 저장해 준 뒤 파일을 스테이지에 올린 후 'work1'이라는 메시지와 함께 커밋해 주었다. 이 작업은 지금까지 계속해오던 작업이라 그리 어렵지는 않다.

> git branch o2
{: data-ke-style="style3"}

이번엔 'o2'라는 브랜치를 만들어 보겠다. 이제 main 브랜치와 o2 브랜치 모두 work1이라는 최신 커밋을 가지고 있다.

다음으로 main 브랜치에 main.txt 파일을 하나 더 만들겠다. main.txt 파일을 생성하고 'main2'라고 입력한 후 저장한다. 그리고 'main work2'라는 메시지와 함께 커밋해 주었다.

지금까지 main 브랜치에서 work1 커밋과 main work2 커밋을 만들었다. 이제 o2 브랜치로 전환해 보겠다.

> git switch o2
{: data-ke-style="style3"}

o2 브랜치에서 o2.txt 파일을 만들고 '2'라는 내용을 입력한 후 저장해 주었다. o2.txt 파일은 'o2 work 2'라는 메시지로 커밋해 주었다.

한번 git log 명령을 통해 현재 커밋 상태를 확인해 보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="325" data-origin-height="95"><span data-url="/assets/images/posts/dcb61e1ab38019d69ad5353bc8d1304a68f4c301.png" data-phocus="/assets/images/posts/dcb61e1ab38019d69ad5353bc8d1304a68f4c301.png"><img src="/assets/images/posts/dcb61e1ab38019d69ad5353bc8d1304a68f4c301.png" loading="lazy" width="325" height="95" data-origin-width="325" data-origin-height="95"></span></figure>

work1 커밋은 main 브랜치와 o2 브랜치가 똑같이 가지고 있다. 이어서 main 브랜치에는 main work2 커밋이 생겼고 o2 브랜치에는 o2 work 2 커밋이 생겼다. main 브랜치 입장에서 main work1 -&gt; main work2 순으로 커밋이 생겼고, o2 브랜치 입장에서 main work1 -&gt; o2 work2 순으로 커밋이 생겼다.

이제 o2 브랜치에서 작업이 모두 끝났다고 가정해 보자. 그렇다면 o2 브랜치의 내용을 main 브랜치로 병합해 보자. 브랜치를 병합하려면 먼저 main 브랜치로 전환해야 한다.

> git swich main
{: data-ke-style="style3"}

브랜치를 병합할 대는 git merge 명령 뒤에 가져올 브랜치 이름을 적는다. main 브랜치를 기준으로 o2 브랜치를 가져와 병합하려면 git merge o2와 같이 입력한다.

> git merge o2
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="652" data-origin-height="347"><span data-url="/assets/images/posts/fe92fbbeef157184574c79bf454d79be4b23d2d5.png" data-phocus="/assets/images/posts/fe92fbbeef157184574c79bf454d79be4b23d2d5.png"><img src="/assets/images/posts/fe92fbbeef157184574c79bf454d79be4b23d2d5.png" loading="lazy" width="652" height="347" data-origin-width="652" data-origin-height="347"></span></figure>

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="266" data-origin-height="99"><span data-url="/assets/images/posts/92a2082228898954da63c97fbc87e1b802bf2877.png" data-phocus="/assets/images/posts/92a2082228898954da63c97fbc87e1b802bf2877.png"><img src="/assets/images/posts/92a2082228898954da63c97fbc87e1b802bf2877.png" loading="lazy" width="266" height="99" data-origin-width="266" data-origin-height="99"></span></figure>

자동으로 편집창이 열리면서 'Merge branch o2'라는 커밋 메시지가 나타난다. 브랜치를 병합하면서 만들어진 커밋 메시지이다. 커밋 메시지를 수정할 수도 있고 그대로 사용해도 되지만 나는 그대로 사용하기 위해서 커밋 메시지가 타나난 탭을 닫아주었다. 그럼 브랜치가 병합되었다는 커밋이 자동으로 만들어진다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="377" data-origin-height="135"><span data-url="/assets/images/posts/838f968b1fd02ea6eb16e487ebe70209cad5db07.png" data-phocus="/assets/images/posts/838f968b1fd02ea6eb16e487ebe70209cad5db07.png"><img src="/assets/images/posts/838f968b1fd02ea6eb16e487ebe70209cad5db07.png" loading="lazy" width="377" height="135" data-origin-width="377" data-origin-height="135"></span></figure>

git log --oneline --branches --graph 명령으로 브랜치와 커밋이 어떻게 병합되었는지 확인하였다. o2 work2 커밋이 main 브랜치에 병합되면서 " Merge branch 'o2' "라는 커밋이 새로 생겼다. 이처럼 두 브랜치엣 ㅓ서로 다른 파일을 병합하는 경우 이렇게 깃에서 간단히 해결할 수 있다.

#### <strong>서로 다른 브랜치에서 한 문서의 다른 부분을 수정했을 때 병합하기</strong>

방금까지 했던 것처럼 2개의 브랜치에 서로 다른 문서가 있다면 브랜치를 병합하기 쉽다. 이번에는 2개의 브랜치에서 같은 문서를 수정한다면 어떻게 병합하는지 병합하는 과정을 알아보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="612" data-origin-height="144"><span data-url="/assets/images/posts/9c6e79355294f2ff1df85073b58b931e678e7b44.png" data-phocus="/assets/images/posts/9c6e79355294f2ff1df85073b58b931e678e7b44.png"><img src="/assets/images/posts/9c6e79355294f2ff1df85073b58b931e678e7b44.png" loading="lazy" width="612" height="144" data-origin-width="612" data-origin-height="144"></span></figure>

기존에 작업했던 폴더는 닫아주고 merge2라는 새로운 디렉터리를 만들어 주었다. 이후 git init 명령을 입력해 주었다. work.txt 파일을 만든 다음 내용을 입력해 주었다. 방금 만든 work.txt를 스테이지에 올리고 커밋해 준다. 커밋 메시지는 'work1'라고 하겠다. 여기까지는 기존 작업과 동일하다.

이제 새로운 브랜치를 만들어보겠다. 'o2'라는 새로운 브랜치를 만들어주면 main 브랜치와 o2 브랜치에는 work1 커밋이 있게 된다.

양쪽 브랜치 모두 work.txt가 있는 상태에서 우선 main 브랜치에서 문서를 수정해 보겠다. work.txt 문서에는 #title과 content가 각각 2개씩 있다. 그중에서 첫 번째 content 다음 줄에 'main content2'라고 입력한 후 저장해 주었다. 수정한 work.txt를 커밋해 주는데 이때 커밋 메시지는 'main work2'라고 하겠다.

> git switch o2
{: data-ke-style="style3"}

이제 o2 브랜치로 전환하여 o2브랜치의 work.txt 파일도 수정해 보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="390" data-origin-height="161"><span data-url="/assets/images/posts/ebd4245b7577f1fcc7fdc8c2d5a5ccb044feba4a.png" data-phocus="/assets/images/posts/ebd4245b7577f1fcc7fdc8c2d5a5ccb044feba4a.png"><img src="/assets/images/posts/ebd4245b7577f1fcc7fdc8c2d5a5ccb044feba4a.png" loading="lazy" width="390" height="161" data-origin-width="390" data-origin-height="161"></span></figure>

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="344" data-origin-height="67"><span data-url="/assets/images/posts/3f77e94c64c704f4a0cb31db729057210635e251.png" data-phocus="/assets/images/posts/3f77e94c64c704f4a0cb31db729057210635e251.png"><img src="/assets/images/posts/3f77e94c64c704f4a0cb31db729057210635e251.png" loading="lazy" width="344" height="67" data-origin-width="344" data-origin-height="67"></span></figure>

이어서 work.txt 파일에서 두 번째 contetn 다음 줄에 'o2 content2'라고 입력하고 저장한다. 수정한 work.txt 커밋하고, 커밋 메시지는 'o2 work2'라고 하겠다.

> git switch main
{: data-ke-style="style3"}

main 브랜치와 o2 브랜치 양쪽에서 work.txt 파일을 수정했지만 문서 안의 수정 위치는 다르다. 이 상태에서 병합을 해보겠다. o2 브랜치를 main 브랜치에 합치기 위해 main 브랜치로 전환해 주었다.

> git  
> merge   
> o2
{: data-ke-style="style3"}

git merge 명령을 사용해 o2 브랜치를 main 브랜치로 끌어와주었다. 그러면 커밋 메시지가 자동으로 나타날 것인데 메시지를 수정할 수도 있고 그대로 사용할 수도 있다. 나는 수정 없이 커밋 메시지 탭을 닫아주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="361" data-origin-height="92"><span data-url="/assets/images/posts/ae4396e68d62fc513a9beb41b2f90f2165ba732c.png" data-phocus="/assets/images/posts/ae4396e68d62fc513a9beb41b2f90f2165ba732c.png"><img src="/assets/images/posts/ae4396e68d62fc513a9beb41b2f90f2165ba732c.png" loading="lazy" width="361" height="92" data-origin-width="361" data-origin-height="92"></span></figure>

터미널 창에는 Auto-merging work.txt로 시작하는 병합 완료 메시지가 나타난다. main 브랜치의 work.txt를 보면 main 브랜치의 수정 내용과 o2 브랜치의 수정 내용이 자연스럽게 하나의 파일에 합쳐진 것을 볼 수 있다. 이렇게 깃에는 같은 문서로 서로 다른 위치를 수정했을 경우 자동으로 합쳐 주는 기능이 있다는 사실을 알게 되었다.

#### <strong>서로 다른 브랜치에서 한 문서의 같은 부분을 수정했을 때 병합하기</strong>

깃에서는 줄 단위로 변경 여부를 확인하므로 서로 다른 브랜치에서 같은 문서의 같은 줄을 수정했을 경우, 브랜치를 병합하면 브랜치 충돌(conflict)이 발생한다. main 브랜치와 o2 브랜치에서 같은 파일의 같은 위치를 수정한 후 병합해 보면서 어떤 경우에 브랜치 충돌이 생기는지, 충돌은 어떻게 해결하는지 알아보겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="321" data-origin-height="77"><span data-url="/assets/images/posts/77b9d6b1f73e427031f777d84b0f363fa4d6a2d0.png" data-phocus="/assets/images/posts/77b9d6b1f73e427031f777d84b0f363fa4d6a2d0.png"><img src="/assets/images/posts/77b9d6b1f73e427031f777d84b0f363fa4d6a2d0.png" loading="lazy" width="321" height="77" data-origin-width="321" data-origin-height="77"></span></figure>

방금까지 작업한 폴더를 닫고 merge3라는 새로운 디렉터리를 만들었다. 이후 터미널 창에서 git init 명령을 사용해 저장소로 만들어주었다. 이후 merge2 디렉터리때 했던 것처럼 work.txt 파일을 만들고 내용을 입력해 주었다. 이때 2가지 내용 사이에 빈 줄을 하나만 두었다. 그리고. work.txt를 스테이지에 올리고 커밋해 주었다. 여기서 커밋 메시지는 'work1'이라고 하겠다.

> git branch o2
{: data-ke-style="style3"}

이제 o2라는 브랜치를 만든다. o2 브랜치는 main 브랜치의 최신 커밋을 가져온다. 따라서 work.txt는 브랜치 양쪽 모두에 있겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="483" data-origin-height="143"><span data-url="/assets/images/posts/bbd20b6bc79d604e76371a69bf5e958a4ebdbf43.png" data-phocus="/assets/images/posts/bbd20b6bc79d604e76371a69bf5e958a4ebdbf43.png"><img src="/assets/images/posts/bbd20b6bc79d604e76371a69bf5e958a4ebdbf43.png" loading="lazy" width="483" height="143" data-origin-width="483" data-origin-height="143"></span></figure>

현재 브랜치인 main에서 먼저 work.txt를 수정하겠다. work.txt 문서에는 첫 번째 content 다음 줄에 'main content2'라고 입력한 후 저장해 주었다.

> git commit -am "main work2"
{: data-ke-style="style3"}

수정한 work.txt를 커밋해 주었다. 이때 커밋 메시지는 'main work2'라고 해주었다.

> git switch o2
{: data-ke-style="style3"}

이제 o2 브랜치의 work.txt 파일을 수정해 보자. 먼저 o2 브랜치로 전환해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="460" data-origin-height="126"><span data-url="/assets/images/posts/ebe7c9389515337bce03e61689fc276eb28269a5.png" data-phocus="/assets/images/posts/ebe7c9389515337bce03e61689fc276eb28269a5.png"><img src="/assets/images/posts/ebe7c9389515337bce03e61689fc276eb28269a5.png" loading="lazy" width="460" height="126" data-origin-width="460" data-origin-height="126"></span></figure>

main 브랜치에서 추가 내용을 입력한 위치와 같은 곳에서 'o2 content2'라고 입력하고 저장해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="351" data-origin-height="54"><span data-url="/assets/images/posts/ab3a808719dbe8ab1b2050fc325d144c7053d7f2.png" data-phocus="/assets/images/posts/ab3a808719dbe8ab1b2050fc325d144c7053d7f2.png"><img src="/assets/images/posts/ab3a808719dbe8ab1b2050fc325d144c7053d7f2.png" loading="lazy" width="351" height="54" data-origin-width="351" data-origin-height="54"></span></figure>

수정한 work.txt 파일을 커밋해 주고, 커밋 메시지는 'o2 work2'라고 하였다.

main 브랜치와 o2 브랜치 양쪽에서 work.txt 파일을 수정했는데 수정 위치를 같게 하였다. 이럴 경우 어떻게 병합되는지 알아보겠다.

> git switch main  
> git merge o2
{: data-ke-style="style3"}

o2 브랜치를 main 브랜치에 병합하기 위해 먼저 main 브랜치로 전환한 후, git merge 명령을 사용해 o2 브랜치를 병합해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="805" data-origin-height="211"><span data-url="/assets/images/posts/437ff86281adaaeeed4bf668fd996ec3616f8021.png" data-phocus="/assets/images/posts/437ff86281adaaeeed4bf668fd996ec3616f8021.png"><img src="/assets/images/posts/437ff86281adaaeeed4bf668fd996ec3616f8021.png" loading="lazy" width="805" height="211" data-origin-width="805" data-origin-height="211"></span></figure>

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="469" data-origin-height="82"><span data-url="/assets/images/posts/7b86de5c391aad2928dd1964e4d38859ce7b8103.png" data-phocus="/assets/images/posts/7b86de5c391aad2928dd1964e4d38859ce7b8103.png"><img src="/assets/images/posts/7b86de5c391aad2928dd1964e4d38859ce7b8103.png" loading="lazy" width="469" height="82" data-origin-width="469" data-origin-height="82"></span></figure>

터미널 창에서 work.txt를 자동 병합하는 동안 충돌이 발생했다는 메시지가 나타난다. 이 상태에서 work.txt 파일을 보면 '&lt;&lt;&lt;&lt;&lt;&lt;&lt; HEAD'와 '=======' 사이에는 현재 브랜치, 즉 main 브랜치에서 수정한 내용이고, '======='과 '&gt;&gt;&gt;&gt;&gt;&gt;&gt; o2' 커밋 해시 사이는 o2 브랜치에서 수정한 내용이다. 이 2가지 내용이 충돌한다는 뜻이다. 이 문제는 사용자가 직업 해결해야 한다. 화면 오른쪽 아래 나타난 "병합 편집기에서 확인" 버튼을 클릭해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="1390" data-origin-height="315"><span data-url="/assets/images/posts/5c9e5709c7bdffe39d49d5abed70eacf55d4846f.png" data-phocus="/assets/images/posts/5c9e5709c7bdffe39d49d5abed70eacf55d4846f.png"><img src="/assets/images/posts/5c9e5709c7bdffe39d49d5abed70eacf55d4846f.png" loading="lazy" width="1390" height="315" data-origin-width="1390" data-origin-height="315"></span></figure>

화면이 3개로 분할되면서 o2 브랜치(수신)에서 수정한 내용, main 브랜치(현재)에서 수정한 내용이 나란히 나타나고, 아래쪽 화면에는 병합 결과가 나타난다. 위에 있는 화면 2개를 보면서 아래 화면에서 충돌이 생기지 않도록 수정하면 된다. 

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="1138" data-origin-height="335"><span data-url="/assets/images/posts/131b36ddb13bc35d01d230e40c2f9117067a7adf.png" data-phocus="/assets/images/posts/131b36ddb13bc35d01d230e40c2f9117067a7adf.png"><img src="/assets/images/posts/131b36ddb13bc35d01d230e40c2f9117067a7adf.png" loading="lazy" width="1138" height="335" data-origin-width="1138" data-origin-height="335"></span></figure>

\[현재 수락\]은 main 브랜치의 수정 내용을 적용한다는 뜻이고, \[수신 수락\]은 병합할 o2 브랜치의 수정 내용을 적용한다는 뜻이다. \[현재 수락\]이나 \[수신 수락\]을 클릭하는 순서에 따라 수정 내용이 차례로 적용된다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="430" data-origin-height="140"><span data-url="/assets/images/posts/1c3ae9898bad55808213b38d0d2ed431f970d957.png" data-phocus="/assets/images/posts/1c3ae9898bad55808213b38d0d2ed431f970d957.png"><img src="/assets/images/posts/1c3ae9898bad55808213b38d0d2ed431f970d957.png" loading="lazy" width="430" height="140" data-origin-width="430" data-origin-height="140"></span></figure>

충돌이 더 이상 생기지 않는다면 "병합 완료" 버튼을 클릭한다. 여기에서는 2개의 수정 사항을 모두 반영해 주었다. work.txt파일을 확인해 주면 main 브랜치와 o2 브랜치의 수정 내용이 모두 반영된 것을 확인할 수 있다.

> git commit -am "merge o2 branch"
{: data-ke-style="style3"}

이제 수정한 work.txt를 스테이지에 올리고 커밋하면 된다. 커밋 메시지는 merge o2 branch로 해주었다. 이렇게 해서 o2 브랜치에서 병합한 work.txt의 충돌을 해결하고 커밋을 끝냈다.

> git log --oneline --branches --graph
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="357" data-origin-height="124"><span data-url="/assets/images/posts/8602572d6a74209b154309f6b8154bf8385f4b17.png" data-phocus="/assets/images/posts/8602572d6a74209b154309f6b8154bf8385f4b17.png"><img src="/assets/images/posts/8602572d6a74209b154309f6b8154bf8385f4b17.png" loading="lazy" width="357" height="124" data-origin-width="357" data-origin-height="124"></span></figure>

git log 명령을 사용하여 지금까지 만든 브랜치와 커밋 관계를 확인해 주었다.

#### <strong>병합이 끝난 브랜치 삭제하기</strong>

브랜치를 병합한 후 더 이상 사용하지 않는 브랜치는 깃에서 삭제할 수 있다. 하지만 이렇게 브랜치를 삭제하더라도 완전히 지워지는 것은 아니며 같은 이름의 브랜치를 만들면 예전 내용을 다시 볼 수 있다. 한번 확인해 보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="383" data-origin-height="69"><span data-url="/assets/images/posts/574c496e6b0ef8f7cf837a0104633c6041295fdf.png" data-phocus="/assets/images/posts/574c496e6b0ef8f7cf837a0104633c6041295fdf.png"><img src="/assets/images/posts/574c496e6b0ef8f7cf837a0104633c6041295fdf.png" loading="lazy" width="383" height="69" data-origin-width="383" data-origin-height="69"></span></figure>

git branch 명령을 사용하면 현재 저장소에 어떤 브랜치가 있는지 확인할 수 있다. 현재 main 브랜치와 o2 브랜치가 있는 것이 확인이 될 거다. 그리고 현재 브랜치는 main이므로 main 브랜치 앞에 \* 표시가 되어 있다.

> git branch -d o2
{: data-ke-style="style3"}

이제 브랜치를 한번 삭제해 보자. 브랜치를 삭제할 때는 git branch 명령에 -d 옵션을 추가한 후 그 뒤에 삭제할 브랜치 이름을 사용한다. 다음과 같이 입력해서 o2 브랜치를 삭제해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="275" data-origin-height="51"><span data-url="/assets/images/posts/b7ce5880d6480a541179d2d292b6d3e1d24da95f.png" data-phocus="/assets/images/posts/b7ce5880d6480a541179d2d292b6d3e1d24da95f.png"><img src="/assets/images/posts/b7ce5880d6480a541179d2d292b6d3e1d24da95f.png" loading="lazy" width="275" height="51" data-origin-width="275" data-origin-height="51"></span></figure>

다음처럼 Deleted branch o2라고 메시지가 나타나면 브랜치 삭제에 성공한 것이다. 삭제한 브랜치는 같은 이름으로 다시 브랜치를 만들면 예전에 작업했던 내용이 그대로 나타난다. 즉, 브랜치를 삭제한다는 것은 저장소에서 완전히 없애는 것이 아니라 깃의 흐름 속에서 감추는 것이라고 생각하면 된다.

#### <strong>cherry-pick으로 병합하기</strong>

앞에서 사용한 병합하는 과정 외에 깃에는 cherry-pick이라는 또 하나의 병합 방법이 있다. 이전 병합 방법과는 달리 브랜치 전체가 아니라 특정 커밋의 변경 내용만 합칠 때 사용하는 기능이다. 한번 실습을 통해 자세히 알아보자. 

지금까지 작업한 폴더는 닫아주고 cherry-pick이라는 새로운 디렉터리를 만든 뒤 작업 폴더로 추가해 주었다. 이후 git init 명령을 사용하여 깃 저장소로 만들어주었다.

> git add init.txt; git commit -m "init"
{: data-ke-style="style3"}

여기에서는 파일 내용을 수정하는 것이 아니라 버전이 필요하기 때문에 빈 파일을 만들고 커밋하겠다. init.txt 파일을 만든 후 내용 없이 저장해 준다. 그리고 'init'이라는 메시지와 함께 커밋한다. 터미널에서는 세미콜론(;)으로 구분해서 여러 명령을 한꺼번에 처리할 수 있다.

> git branch topic  
> git log --oneline --all --graph
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="300" data-origin-height="48"><span data-url="/assets/images/posts/76b02ce17c8764852de4ed5f9c2ac48cbd01a6e6.png" data-phocus="/assets/images/posts/76b02ce17c8764852de4ed5f9c2ac48cbd01a6e6.png"><img src="/assets/images/posts/76b02ce17c8764852de4ed5f9c2ac48cbd01a6e6.png" loading="lazy" width="300" height="48" data-origin-width="300" data-origin-height="48"></span></figure>

이 상태에서 새로운 브랜치 topic을 만들어주었다. 그리고 깃 로그를 확인해 보면 init이라는 커밋이 main과 topic 브랜치 양쪽에 있다. 여기에서 --all 옵션은 최신 커밋뿐만 아니라 모든 커밋을 다 보여준다.

> touch m1; git add m1; git commit -m "m1"  
> touch m2; git add m2; git commit -m "m2"  
> git log --oneline --all --graph
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="272" data-origin-height="82"><span data-url="/assets/images/posts/c6273829d023536f4cd50ecff09565a6c5a4679b.png" data-phocus="/assets/images/posts/c6273829d023536f4cd50ecff09565a6c5a4679b.png"><img src="/assets/images/posts/c6273829d023536f4cd50ecff09565a6c5a4679b.png" loading="lazy" width="272" height="82" data-origin-width="272" data-origin-height="82"></span></figure>

이제 main 브랜치에 m1과 m2라는 버전 2개를 더 만들어 보겠다. 다음 명령에서 touch는 빈 파일을 만드는 명령어이다. 그리고 git log로 확인해 보면 main 브랜치는 최신 버전 m2를 가리키고 있고, topic 브랜치에는 init 버전 상태인 것을 볼 수 있다.

> git switch topic  
> touch t1; git add t1; git commit -m "t1"  
> touch t2; git add t2; git commit -m "t2"  
> touch t3; git add t3; git commit -m "t3"
{: data-ke-style="style3"}

topic 브랜치로 전환한 후, 앞에서와 같은 방법으로 t1, t2, t3 버전을 만들었다. 한번 git log로 확인해 보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="290" data-origin-height="147"><span data-url="/assets/images/posts/801844eff1051291ab3c6d101b4fc4d06748b203.png" data-phocus="/assets/images/posts/801844eff1051291ab3c6d101b4fc4d06748b203.png"><img src="/assets/images/posts/801844eff1051291ab3c6d101b4fc4d06748b203.png" loading="lazy" width="290" height="147" data-origin-width="290" data-origin-height="147"></span></figure>

main 브랜치는 init 버전부터 시작해서 m1, m2 버전으로 연결되어 있고, topic 브랜치는 init 버전부터 시작해서 t1, t2, t3 버전으로 연결된다.

현재 브랜치가 2개 있는데 topic 브랜치의 여러 버전 중 하나를 골라서(pick) main 브랜치에 적용하고 싶을 때 체리픽(cherry-pick)을 사용한다. 여기에서는 topic 브랜치의 t2 버전을 main 브랜치에 병합해 보겠다.

> git switch main  
> git cherry-pick \[커밋 해시\]
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="397" data-origin-height="100"><span data-url="/assets/images/posts/124bfecf5c5a9428da331747ed2ee371d54f9cc8.png" data-phocus="/assets/images/posts/124bfecf5c5a9428da331747ed2ee371d54f9cc8.png"><img src="/assets/images/posts/124bfecf5c5a9428da331747ed2ee371d54f9cc8.png" loading="lazy" width="397" height="100" data-origin-width="397" data-origin-height="100"></span></figure>

먼저 topic 브랜치에서 픽할 t2 커밋의 해시를 선택한 후 복사한다. 체리픽을 사용하기 위해 이제 main 브랜치로 전환해야 한다. 그리고 cherry-pick 명령 뒤에 복사한 t2 커밋의 해시를 붙여 넣는다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="335" data-origin-height="52"><span data-url="/assets/images/posts/56a805f9012de12a8f1d652d468f75f0969421cc.png" data-phocus="/assets/images/posts/56a805f9012de12a8f1d652d468f75f0969421cc.png"><img src="/assets/images/posts/56a805f9012de12a8f1d652d468f75f0969421cc.png" loading="lazy" width="335" height="52" data-origin-width="335" data-origin-height="52"></span></figure>

ls 명령으로 main 브랜치에 어떤 파일이 있는지 살펴보니 기존에 main 브랜치에 잇던 init.txt, m1, m2 다음에 t2가 합쳐진 것을 볼 수 있다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="383" data-origin-height="159"><span data-url="/assets/images/posts/abac1af441879643244e0fd7776b65a69205220f.png" data-phocus="/assets/images/posts/abac1af441879643244e0fd7776b65a69205220f.png"><img src="/assets/images/posts/abac1af441879643244e0fd7776b65a69205220f.png" loading="lazy" width="383" height="159" data-origin-width="383" data-origin-height="159"></span></figure>

 그리고 깃 로그를 확인해 보면, topic 브랜치에 t2가 있고, main 브랜치에도 t2가 추가되어 있을 것이다.
