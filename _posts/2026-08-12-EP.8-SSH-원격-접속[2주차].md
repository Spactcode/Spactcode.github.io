### <strong>#깃허브에 SSH 원격 접속하기</strong>

이번에는 HTTPS 방식이 아닌 SSH 방식으로 깃허브에 접속하는 방법을 알아보자.

#### <strong>SSH 원격 접속이란</strong>

SSH 방식으로 접속하는 방법을 알아보기 전 SSH가 무엇인지부터 살펴보자.

SSH는 secure shell의 줄임말로 보안이 강화된 안전한 방법으로 정보를 교환하는 방식이다. SSH에서는 기본적으로 프라이빗 키(private key)와 퍼블릭 키(public key)를 한 쌍으로 묶어서 컴퓨터를 인증한다. 이때 private은 '사적인, 비밀의, 비공개의'를, public은 '공적인, 공개의'를 뜻한다. 퍼블릭 키는 말 그대로 외부로 공대되고, 프라이빗 키는 아무도 알 수 없게 사용자 컴퓨터에만 저장된다. 사용자 컴퓨터에서 SSH키 생성기를 실행하면 프라이빗 키와 퍼블릭 키가 만들어진다.

일반적으로 깃허브의 원격 저장소에 작업을 하려면 ID와 PW를 입력해서 깃허브에게 자신이 해당 저장소를 만든 계정 주인임을 인증해야 한다. 이에 비해 SSH 원격 접속은 프라이빗 키와 퍼블릭 키를 사용해 현재 사용하는 기기를 깃허브에 인증하는 방식이다.

#### <strong>SSH 키 생성하기</strong>

이번에는 퍼블릭 키와 프라이빗 키를 만들어 보고, 이 키들이 어디에 저장되고 어떤 용도로 사용되는지 알아보자.

> cd &#126;
{: data-ke-style="style3"}

터미널 창에 위와 같이 입력해 홈 디렉터리로 이동한다. (나는 SSH키를 홈 디렉터리에 저장할 것이기 때문에 이동하였다.)

> ssh-keygen -t ed25519 -C "email address"
{: data-ke-style="style3"}

ssh-keygen 명령을 실행한다. 맨 뒤에는 저장소에서 사용할 이메일 계정을 입력한다. -t ed25519 옵션은 ed25519라는 알고리즘을 사용해 SSH 키를 만들기 위한 것이고 -C "email address" 옵션은 키에 이메일 주소를 주석으로 기록하는 옵션이다.

> ed25519 알고리즘이란?  
> Edwards-curve Digital Signature Algorithm으로 에드워즈 곡선 디지털 서명 알고리즘이다. 뒤틀린 에드워즈 곡선에 기반한 슈노어 서명의 일종을 사용하는 디지털 서명 기법으로 현존하는 디지털 서명 기법보다 더 빠르면서도 보안성을 유지하기 위해 고안되었다.
{: data-ke-style="style3"}

명령을 입력해 주고 따로 파일 이름을 변경하지 않기 위해 Enter를 계속 눌러주었다. 그러면 SSH 키가 만들어진 것을 확인할 수 있다.

> cd .ssh  
> ls -la
{: data-ke-style="style3"}

이제 키가 잘 만들어졌는지 확인해 보자. 위와 같이 입력해서 .ssh 디렉터리로 이동한 후 그 안에 있는 파일을 살펴보겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="427" data-origin-height="110"><span data-url="/assets/images/posts/ff12c6723c5c3042226a8a091d2f87a4f6be0219.png" data-phocus="/assets/images/posts/ff12c6723c5c3042226a8a091d2f87a4f6be0219.png"><img src="/assets/images/posts/ff12c6723c5c3042226a8a091d2f87a4f6be0219.png" loading="lazy" width="427" height="110" data-origin-width="427" data-origin-height="110"></span></figure>

.ssh 디렉터리에 id\_ed25519 파일과 id\_ed25519.pub 파일이 만들어진 것을 확인할 수 있다. id\_ed25519 파일은 프라이빗 키이므로 사용자 시스템에 보관해 두고 id\_ed25519.pub 파일은 퍼블릭 키이므로 깃허브에 등록할 것이다.

> eval "$(ssh-agent -s)"  
> ssh-add &#126;/.ssh/id\_ed25519
{: data-ke-style="style3"}

위와 같이 명령을 입력하여 사용자 시스템에서 SSH 에이전트를 실행하고 프라이빗 키를 등록한다. SSH 키의 이름을 다르게 지정했다면 id\_ed25519 부분을 수정해 주면 된다. 만약 "Identity added:"라는 메시지가 나타나면 프라이빗 키가 정상으로 추가된 것이다.

#### <strong>깃허브에 퍼블릭 키 전송하기</strong>

앞에서 만든 키를 사용해 보기 전에 SSH 방식으로 깃허브 저장소에 접속하는 과정을 간단히 살펴보자.

SSH 방식으로 접근하려면 먼저 사용자 컴퓨터에 만들어져 있는 퍼블릭 키를 깃허브 서버로 전송한 다음 저장한다. 사용자 컴퓨터에서 깃허브 저장소에 접속하면 사용자 컴퓨터에 잇는 프라이빗 키와 깃허브 서버에 있는 퍼블릭 키를 비교한다. 퍼블릭 키와 프라이빗 키는 한 쌍이므로 두 키가 서로 맞으면 사용자 컴퓨터와 깃허브 저장소가 연결된다.

이제 SSH 방식을 사용해 깃허브에 직접 접속해 보자. SSH 접속은 계정 전체에 적용된다. 만약 spact 계정을 SSH로 접속한다면 이 계정에서 만든 모든 저장소에서 같은 방식으로 사용한다.

> clip &lt; &#126;/.ssh/id\_ed25519.pub
{: data-ke-style="style3"}

SSH로 접속하려면 만들어 놓은 퍼블릭 키를 깃허브에 등록해야 한다. 이때 clip 명령을 사용해서 id\_ed25519.pub 파일의 내용을 복사한다. ( &lt; 기호 다음에 잇는 파일의 내용을 클립보드로 복사한다.)

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="922" data-origin-height="625"><span data-url="/assets/images/posts/5b5b1a17a42dada37fb3369655f98483733c34eb.png" data-phocus="/assets/images/posts/5b5b1a17a42dada37fb3369655f98483733c34eb.png"><img src="/assets/images/posts/5b5b1a17a42dada37fb3369655f98483733c34eb.png" loading="lazy" width="922" height="625" data-origin-width="922" data-origin-height="625"></span></figure>

웹 브라우저에서 깃허브에 접속한 후 사용자 아이콘을 클릭하여 세팅창으로 이동한다. 이후 Access 카테고리에서 SSH and GPG keys를 선택하고 새로운 퍼블릭 키를 추가하기 위해 화면 오른쪽의 New SSh key를 클릭한다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="932" data-origin-height="668"><span data-url="/assets/images/posts/022a681d5d94a97ecc98ae660631ccd57669c8d7.png" data-phocus="/assets/images/posts/022a681d5d94a97ecc98ae660631ccd57669c8d7.png"><img src="/assets/images/posts/022a681d5d94a97ecc98ae660631ccd57669c8d7.png" loading="lazy" width="932" height="668" data-origin-width="932" data-origin-height="668"></span></figure>

SSH에는 퍼블릭 키를 여러 개 등록할 수 있다. 현재 등록하는 SSH 퍼블릭 키를 쉽게 알아볼 수 있도록 Title 항목에 제목을 붙인다. 나는 알아보기 쉽게 window11이라고 작성해 주었다. 그리고 key 항목에 앞에서 복사한 퍼블릭 키값을 붙여 넣고 add SSH key를 클릭해 SSH 키를 추가한다. 이후 인증 창이 보이면 인증까지 완료해 주면 된다.

앞에서 만든 SSH 퍼블릭 키를 깃허브 서버에 올렸다. 이제 SSH 키를 만들었던 컴퓨터는 깃 허브 저장소의 SSH 주소만 알면 따로 로그인 정보를 입력하지 않고도 깃허브 저장소에 접속할 수 있다.

#### <strong>SSH 주소로 원격 저장소 연결하기</strong>

SSH 접속 준비가 끝났다. 이제 SSH 주소를 사용해 지역 저장소와 원격 저장소를 연결해 보겠다. 앞에서 만들었던 Doit-study 저장소는 HTTPS 방식으로 접속했다. 이번에는 새로운 지역 저장소를 만들어서 SSH 방식으로 접속해 보겠다. 우선 새로운 원격 저장소를 만드는 방법은 저번과 동일하다. 아래 사진처럼 나올 때까지 진행해 주면 된다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="928" data-origin-height="456"><span data-url="/assets/images/posts/cc0d64b0748415892de0c6102fde38c146dee79c.png" data-phocus="/assets/images/posts/cc0d64b0748415892de0c6102fde38c146dee79c.png"><img src="/assets/images/posts/cc0d64b0748415892de0c6102fde38c146dee79c.png" loading="lazy" width="928" height="456" data-origin-width="928" data-origin-height="456"></span></figure>

저장소가 만들어지면 기본적으로 HTTPS 주소가 나타난다. 나는 SSH 방식으로 접근할 것이므로 SSH를 클릭해서 주소를 복사해 준다.

깃허브에 퍼블릭 키를 추가하고 원격 저장소의 SSH 주소도 알아냈으니 지역 저장소에 연결할 수 있다. VS code에 기존에 작업했던 폴더를 닫아주고 mogakgog-git이라는 새로운 폴더를 작업 폴더로 추가해 주었다. 이후 git init을 입력해 저장소를 초기화해 주었다.

> git remote add origin \[SSH address\]
{: data-ke-style="style3"}

SSH 주소를 사용해 원격 저장소에 연결하는 방법은 HTTPS 방식과 같다. git remote add origin 명령 뒤에 복사한 주소를 붙여 넣어준다. 

> git remote -v
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="417" data-origin-height="59"><span data-url="/assets/images/posts/ff5c6f7fb6a9510914a8ce1025390342e772e999.png" data-phocus="/assets/images/posts/ff5c6f7fb6a9510914a8ce1025390342e772e999.png"><img src="/assets/images/posts/ff5c6f7fb6a9510914a8ce1025390342e772e999.png" loading="lazy" width="417" height="59" data-origin-width="417" data-origin-height="59"></span></figure>

  
오류 메시지 없이 프롬프트가 표시되면 정상으로 연결된 것이다. git remote 명령 뒤에 -v 옵션을 붙여서 어떤 원격 저장소가 연결되었는지 확인할 수 있다.

> git add f.txt  
> git commit -m "ssh test"
{: data-ke-style="style3"}

이제 f.txt라는 파일을 만든 후 "여름방학 모각공"을 입력하고 저장해 주었다. 그리고 스테이징과 커밋을 진행하는데 커밋 메시지는 'ssh test'라고 해주었다.

> git push -u origin main
{: data-ke-style="style3"}

이제 push 명령을 사용해 원격 저장소로 푸시해 주었다. 만약 경고 메시지가 나타난다면 yes를 입력해 주고 Enter를 누르면 푸시가 진행된다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="932" data-origin-height="703"><span data-url="/assets/images/posts/872513562fa55ba9a7e845c0f59e6b0e5de51bef.png" data-phocus="/assets/images/posts/872513562fa55ba9a7e845c0f59e6b0e5de51bef.png"><img src="/assets/images/posts/872513562fa55ba9a7e845c0f59e6b0e5de51bef.png" loading="lazy" width="932" height="703" data-origin-width="932" data-origin-height="703"></span></figure>

깃허브 저장소를 확인해 보면 방금 푸시한 파일이 올라와 있을 것이다. HTTPS와 SSH는 접속 방식만 다를 뿐 지역 저장소와 원격 저장소를 연결하는 방법, 푸시/풀 하는 방법 모두 동일하다는 것을 알 수 있었다.
