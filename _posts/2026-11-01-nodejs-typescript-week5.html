# Node.js

Node.js는 비동기 이벤트 기반의 JavaScript 런타임으로, 확장 가능한 네트워크 애플리케이션을 구축하도록 설계되었다. 아래 코드는 Node.js에서 제공한 코드이며 이 코드에서는 많은 연결을 동시에 처리할 수 있다. 각 연결마다 콜백이 호출되지만, 할 일이 없으면 Node.js는 대기 상태가 된다.

const { createServer } = require('node:http');
const hostname = '127.0.0.1';
const port = 3000;
const server = createServer((req, res) => {
  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/plain');
  res.end('Hello World');
});
server.listen(port, hostname, () => {
  console.log(`Server running at http://${hostname}:${port}/`);

기존의 스레드 기반 모델과 달리 비효율성을 줄이고 락(lock)이 없어 데드락의 위험이 없는 것이 가장 큰 특징이다.

논블로킹 I/O

거의 모든 함수가 I/O 작업 시 프로세스를 차단(Blocking) 하지 않아 수많은 동시 연결을 가볍게 처리할 수 있다.

런타임 내장 이벤트 루프

별도로 이벤트 루프를 실행하는 차단 호출 없이, 스크립트 실행 시 자동으로 이벤트 루프에 진입하고 콜백이 없으면 대기 상태로 전환되는 유연한 구조를 가진다.

웹 및 HTTP 최적화

HTTP를 핵심 구성 요소로 설계하여 데이터 스트리밍과 짧은 지연 시간을 보장하므로 웹 프레임워크 구축에 이상적이다.

멀티 코어 확장성

스레드가 없는 설계임에도 child_process.fork() 및 cluster 모듈을 사용해 자식 프로세스를 생성하고 소켓을 공유하여 다중 코어 간 로드 밸런싱이 가능하다.

런타임 및 아키텍처

JavaScript 런타임 (JavaScript Runtime): 브라우저 외부 환경에서 JavaScript 코드가 실행될 수 있도록 구동 환경과 내장 라이브러리를 제공하는 실행 플랫폼이다.

비동기 (Asynchronous): 작업을 요청한 후 결과를 기다리지 않고 곧바로 다음 코드를 실행하며, 작업이 완료되면 콜백을 통해 처리하는 방식이다.

이벤트 기반 (Event-driven): 프로그램의 흐름이 사용자 입력, 파일 I/O, 네트워크 응답 등 발생한 '이벤트'에 의해 결정되고 제어되는 아키텍처 디자인이다.

스레드 (Thread): 프로세스 내에서 실행되는 작업의 흐름 단위이다. 기존의 스레드 기반 네트워킹은 연결마다 스레드를 할당하므로 상대적으로 비효율적이고 복잡하다.

락 (Lock) / 데드락 (Deadlock): 락은 멀티스레드 환경에서 자원을 보호하기 위한 잠금장치이며, 데드락은 둘 이상의 프로세스나 스레드가 서로가 가진 락을 영원히 기다리며 멈춰 버리는 교착 상태를 의미한다. Node.js는 스레드 기반의 락이 없어 데드락 걱정에서 비교적 자유롭다.

논블로킹 (Non-blocking): I/O 작업(파일 읽기, 네트워크 요청 등)을 요청했을 때 작업이 끝날 때까지 대기하지 않고 즉시 제어권을 반환하여 다른 작업을 수행할 수 있게 하는 방식이다.

이벤트 루프 (Event Loop): Node.js 내부에서 싱글 스레드의 비동기 작업을 처리하기 위해 콜백 함수들을 순환하며 관리하고 실행하는 핵심 런타임 구성 요소이다.

콜백 (Callback): 특정 작업이 완료된 직후 호출되도록 전달되는 함수이다.
프로토콜 및 통신 용어

스트리밍 (Streaming): 대용량 데이터나 미디어를 한 번에 모두 불러오지 않고, 작은 조각(청크) 단위로 연속해서 전송하고 처리하는 방식이다.
확장 및 멀티 코어 용어

자식 프로세스 (Child Process): 메인 프로세스 외에 운영체제 수준에서 별도로 분리되어 실행되는 하위 프로세스(child_process.fork() 등을 통해 생성)입니다.

클러스터 (Cluster): 소켓을 공유하는 여러 개의 프로세스를 생성하여 컴퓨터의 다중 CPU 코어 간에 부하를 분산(로드 밸런싱)할 수 있게 해주는 Node.js 모듈입니다.

로드 밸런싱 (Load Balancing): 둘 이상의 컴퓨터나 프로세스 사이에 작업 부하를 나누어 분산시키는 기술입니다.

# TypeScript

TypeScript는 JavaScript에 타입 시스템을 추가한 언어이다. TypeScript의 핵심은 코드가 무엇을 의도하고 있는지 명확하게 표현할 수 있게 해 준다는 점에 있다. 타입은 단순한 제약이 아니라, 코드의 사용법과 기댓값을 문서처럼 드러내는 도구이다. JavaScript는 유연하고 표현력이 높은 언어이지만, 코드가 커질수록 “이 값이 어떤 형태인지”, “이 함수가 어떤 입력을 기대하는지”를 파악하기 어려워지는 문제가 있다. 이러한 문제를 TypeScript는 이런 불확실성을 compile time에 미리 드러내도록 돕는다.

여기서 TypeScript의 타입은 runtime에는 존재하지 않는데, 이 말은 TypeScript는 실행 방식을 바꾸지 않는다는 것이다. 대신, 실행되기 전에 코드에 대한 더 많은 정보를 제공해 실수를 줄이고, 코드를 읽고 수정하기 쉽게 만들어 준다.

[TypeScript 바로잡기]

1. TypeScript는 JavaScript를 “대체”하는 언어가 아니다.
TypeScript는 JavaScript 위에서 동작하며, 결국 실행되는 코드는 항상 JavaScript이다.

2. TypeScript를 쓰면 코드가 반드시 복잡해진다?
타입을 잘 설계할수록 불필요한 주석, 방어 코드, 문서가 줄어드는 경우가 많다.

3. 모든 것을 타입으로 엄격하게 표현해야 한다?
TypeScript의 목적은 완벽한 타입 모델이 아니라, 적절한 수준의 안전성과 명확함을 얻는 것이다.
