#### <strong># SAST란?</strong>

SAST는 프로그램을 직접 실행하지 않고 소스코드 자체를 구조적으로 분석해 취약점을 찾아내는 보안 테스트 기법이다. 코드를 단순한 텍스트가 아닌 트리 형태의 데이터 구조인 AST(추상 구문 트리)로 변환한 뒤, 위험한 함수 호출이나 검증되지 않은 외부 입력값의 흐름을 프로그래밍 방식으로 추적하여 논리적 결함을 식별한다.

#### <strong># SAST 및 정적코드 분석 알고리즘에 학습하는 이유</strong>

앞으로 진행할 GAST 프로젝트는 외부에서 웹 애플리케이션에 페이로드를 쏘며 취약점을 찾는 DAST(동적 분석) 도구이다. SAST를 먼저 학습하면 백엔드 서버가 특정 공격 페이로드를 내부 코드레벨에서 어떻게 처리하고 왜 취약점이 발생했는지 그 근본 원인을 파악할 수 있다. 따라서 타겟 내부의 논리 흐름을 예측할 수 있으므로 GAST의 탐지 엔진이 취약점 응답을 대조하고 판별하는 알고리즘을 더 정밀하게 설계할 수 있다고 생각했다.

#### <strong># 목표</strong>

TypeScript Compiler API를 다루며 코드를 데이터로서 분석하고 제어하는 원리에 대해 알아보는 것이다.

#### <strong># STEP.1 AST 시각화 탐색 및 컴파일러 기초 실습</strong>

정적 분석기는 트리의 형태를 보고 취약점을 판별한다. 따라서 텍스트로 된 코드가 런타임이나 컴파일러 내부에서 어떤 트리 구조(AST)로 분해되는지 한번 확인해 보겠다. 먼저 웹 브라우저를 통해 <strong>AST Explorer</strong>에 접속해 주었다.

화면에 보이는 구조는 전체적으로 BinaryExpression (이항 표현식) 즉, 좌항과 우항, 그리고 그 사이의 연산자로 구성된 코드이다. "ping -c 4 " + userInput와 같이 두 요소가 결합되는 구조를 나타낸다. 트리 내부는 아래와 같이 해석할 수 있다.

> <strong>left: StringLiteral:</strong> 연산자 왼쪽의 값으로, 텍스트가 <strong>"ping -c 4 "</strong> 인 고정된 문자열 리터럴(변수를 거치지 않고 코드 상에 따옴표로 직접 하드코딩된 고정 문자열 값)이다.  
>   
> <strong>operatorToken:</strong> <strong>PlusToken:</strong> 두 값을 이어 붙이는 <strong>+</strong> 더하기 연산자이다.  
>   
> <strong>right: Identifier:</strong> 연산자 오른쪽의 값으로, <strong>userInput이라는</strong> 이름을 가진 변수(식별자)이다.
{: data-ke-style="style3"}

SAST의 관점에서 보면 스캐너는 코드를 읽다가 exec() 함수의 인자 자리에 이처럼 문자열과 변수가 결합되어 있는 BinaryExpression 이 존재하는 것을 발견하면 "사용자의 입력값이 검증 없이 시스템 명령어로 직접 흘러 들어가고 있다"라고 판단하게 된다. exec() 함수는 명령어 전체를 하나의 문자열로 받아 서브 셸 내부에서 실행하기 때문에, userInput에 &amp;&amp;나 ; 같은 셸 특수 문자가 섞여 있으면 즉각적인 커맨드 인젝션 취약점이 발생하기 때문이다. 

> 서브 셸 내부에서 실행한다 : Node.js가 명령어를 운영체제에 직접 전달하여 실행하는 대신, 중간에 '명령어 해석기(예: 리눅스의 /bin/sh, 윈도우의 cmd.exe)'를 먼저 띄운 뒤 그 해석기에게 전체 명령어를 통째로 넘겨 처리하게 만드는 방식
{: data-ke-style="style3"}

#### <strong># STEP.2 TypeScript Compiler API를 이용한 미니 스캐너 구현</strong>

이제 눈으로 확인한 AST 구조를 바탕으로, 실제 Node.js 환경에서 코드를 읽고 분석하는 정적 탐지기를 직접 작성해 보겠다.

가장 먼저 터미널에서 새로운 폴더를 만들고 TypeScript 컴파일러 API 패키지를 설치한다.

```bash
npm init -y
npm install typescript @types/node ts-node
```

취약점 탐지 스크립트는 아래와 같다. 소스코드를 트리로 파싱한 뒤, 재귀적으로 순회하며 exec 함수 내부에 문자열 결합(+)이 인자로 들어가는 커맨드 인젝션 의심 패턴을 잡아낸다.

```typescript
import * as ts from 'typescript';

const targetCode = `
  import { exec } from 'child_process';
  function executeUserCommand(userInput: string) {
    exec("ping -c 4 " + userInput); 
  }
`;

const sourceFile = ts.createSourceFile('target.ts', targetCode, ts.ScriptTarget.Latest, true);

function visit(node: ts.Node) {
  if (ts.isCallExpression(node)) {
    const funcName = node.expression.getText(sourceFile);
    
    if (funcName === 'exec' && node.arguments.length > 0) {
      const firstArg = node.arguments[0];
      
      if (ts.isBinaryExpression(firstArg)) {
        const { line, character } = sourceFile.getLineAndCharacterOfPosition(node.getStart());
        console.log(`[경고] 라인 ${line + 1}, 위치 ${character + 1}`);
        console.log(`사유: exec() 함수 내부에 검증되지 않은 문자열 결합이 감지되었습니다.`);
      }
    }
  }
  ts.forEachChild(node, visit);
}

visit(sourceFile);
```

작성한 코드를 npx ts-node scanner.ts 명령어로 실행하면, 코드가 텍스트가 아닌 구조화된 데이터로 분석되어 취약점이 발생한 정확한 위치를 터미널에 출력한다.

#### <strong># STEP.3 TypeChecker를 활용한 오염 분석(Taint Analysis) 적용</strong>

정교한 오탐(False Positive) 방지를 위해 변수가 어디서부터 흘러왔는지 추적하는 단계이다. 이 분석을 위해서는 코드를 단순 텍스트로 읽는 것을 넘어, 파일 간의 관계와 변수의 타입 스코프를 분석할 수 있는 ts.createProgram과 TypeChecker 객체가 필요하다.

이를 위해 분석 대상 코드를 메모리가 아닌 실제 파일(target.ts)로 분리하여 진행해 보겠다.

스캐너와 같은 폴더에 target.ts 파일을 만들고 아래 코드를 저장해 주었다.

```typescript
import { exec } from 'child_process';

function unsafeExecute(userInput: string) {
  exec("ping -c 4 " + userInput);
}

function safeExecute() {
  const safeInput = "127.0.0.1";
  exec("ping -c 4 " + safeInput);
}
```

기존 scanner.ts의 내용을 아래와 같이 수정해 주었다.

```javascript
import { createRequire } from 'module';
const require = createRequire(import.meta.url);
const ts = require('typescript');

const program = ts.createProgram(['target.ts'], { target: 99 });
const checker = program.getTypeChecker();
const sourceFile = program.getSourceFile('target.ts');

function visit(node: any) {
  if (ts.isCallExpression(node)) {
    const funcName = node.expression.getText(sourceFile);
    
    if (funcName === 'exec' && node.arguments.length > 0) {
      const firstArg = node.arguments[0];
      
      if (ts.isBinaryExpression(firstArg)) {
        const rightNode = firstArg.right;
        
        if (ts.isIdentifier(rightNode)) {
          const symbol = checker.getSymbolAtLocation(rightNode);
          
          if (symbol && symbol.valueDeclaration) {
            const decl = symbol.valueDeclaration;
            const { line } = sourceFile.getLineAndCharacterOfPosition(node.getStart());
            
            if (ts.isParameter(decl)) {
               console.log(`[위험 감지] 라인 ${line + 1}: 외부 파라미터 '${symbol.name}'(이)가 exec에 사용되었습니다.`);
            } else if (ts.isVariableDeclaration(decl)) {
               console.log(`[통과] 라인 ${line + 1}: 내부 변수 '${symbol.name}'(이)가 exec에 사용되었습니다. (오탐 방지)`);
            }
          }
        }
      }
    }
  }
  ts.forEachChild(node, visit);
}

if (sourceFile) {
  visit(sourceFile);
} else {
  console.error("target.ts 파일을 찾을 수 없습니다.");
}
```

터미널에 node --strip-types scanner.ts 명령어를 통해 다시 스캐너를 실행해 준다.
