### <strong>#커밋 내용 확인하기</strong>

#### <strong>커밋 기록 자세히 살펴보기 - git log</strong>

깃에는 커밋했던 기록을 살펴보는 git log가 있다. git log 명령을 입력하면 지금까지 만든 버전이 화면에 보이고 버전마다 설명도 함께 나타난다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="449" data-origin-height="217"><span data-url="/assets/images/posts/0b4bcc0fe7be1f997ae85894d1b98758a1166b3a.png" data-phocus="/assets/images/posts/0b4bcc0fe7be1f997ae85894d1b98758a1166b3a.png"><img src="/assets/images/posts/0b4bcc0fe7be1f997ae85894d1b98758a1166b3a.png" loading="lazy" width="449" height="217" data-origin-width="449" data-origin-height="217"></span></figure>

commit 항목 오른쪽에 영문과 숫자로 된 긴 문자열이 나타나는데 이것을 커밋 해시(commit hash), 또는 깃 해시(git hash)라고 한다. 커밋을 구별하는 용도라고 생각하면 될 것 같다. 다음으로 커밋 해시 오른쪽에 있는 (HEAD -&gt; main)는 이 번전이 가장 최신이라는 표시이다. Author 항목에는 버전을 누가 만들었는지, Date 항목에는 버전이 언제 만들어졌는지 나타난다. 그 아래에는 작성자가 기록한 커밋 메시지가 나온다. 이렇게 git log 명령을 입력했을 때 나오는 정보를 묶어 간단히 커밋 로그라고 한다.

#### <strong>변경 사항 확인하기 -git diff</strong>

한번 생각해 보자. 우리가 print("Hello World!")라는 코드와 같이 짧은 코드만 작성하는 경우는 얼마나 될까? 대부분은 엄청나게 긴 수만 줄짜리 소스 코드를 작성할 것이다. 그런데 만약 이 소스 코드를 수정한 뒤 저장소에 잇는 최근 버전과 비교해서 어떤 부분이 다른지 찾아야 한다면 어떨까? 이것을 커밋 메시지만으로 구체적으로 어디가 어떻게 수정되었는지 파악하기는 쉽지 않을 것이다. 이때 사용하는 것이 git diff 명령이다. 이 명령을 사용하면 작업 트리와 스테이지에 있는 파일을 비교하거나, 스테이지에 있는 파일과 저장소에 있는 최신 커밋을 비교해서 수정한 파일을 커밋하기 전에 최종 검토할 수 있다.

기존에 작성된 "Good bye&#126;"를 삭제하고 "Do it! study"를 추가한 후 저장해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="544" data-origin-height="144"><span data-url="/assets/images/posts/a49db935ebd9809c066af1b7808bb7680ca7d61b.png" data-phocus="/assets/images/posts/a49db935ebd9809c066af1b7808bb7680ca7d61b.png"><img src="/assets/images/posts/a49db935ebd9809c066af1b7808bb7680ca7d61b.png" loading="lazy" width="544" height="144" data-origin-width="544" data-origin-height="144"></span></figure>

git status 명령을 사용해 깃의 상태를 확인해 보면 hello.txt 파일이 수정되었고, 아직 스테이징 상태가 아니라고 나오는 것을 확인할 수 있다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="405" data-origin-height="198"><span data-url="/assets/images/posts/c52ac28d856476b5b67b8be5c708a0398c58135d.png" data-phocus="/assets/images/posts/c52ac28d856476b5b67b8be5c708a0398c58135d.png"><img src="/assets/images/posts/c52ac28d856476b5b67b8be5c708a0398c58135d.png" loading="lazy" width="405" height="198" data-origin-width="405" data-origin-height="198"></span></figure>

방금 수정한 hello.txt 파일이 저장소에 있는 최신 버전의 hello.txt와 어떻게 다른지 git diff 명령을 통해 알아보았다. 여러 내용이 있지만 이 중 "\-Good bye&#126;"를 통해 최신 버전과 비교할 때 hello.txt. 파일에서 "Good bye&#126;"가 삭제되었다는 것을 확인할 수 있다. 또한 "+Do it! study"를 통해 hello.txt파일에 "Do it! study"라는 내용이 추가되었다는 뜻이다.

이렇게 작업 트리에 수정한 파일과 최신 버전을 비교한 후 수정한 내용으로 다시 버전을 만들려면 스테이지에 올린 후 커밋하면 된다.

### <strong>#버전 만드는 단계마다 파일 상태 알아보기</strong>

깃에서는 버전을 만드는 단계마다 파일 상태가 달라진다. 그래서 파일 상태를 이해하면 이 파일이 버전 관리의 여러 단계 중 어디에 해당하는지, 그 상태에서 어떤 일을 할 수 있는지 알 수 있다. 하지만 파일 상태는 눈에 보이지 않는다고 한다. 그래서 지금 당장 이해하기 어렵다면 깃 사용이 좀 더 익숙해진 후에 다시 살펴보는 것을 책에서 추천하고 있다.

#### <strong>tracked 파일과 untracked 파일</strong>

git status 명령을 사용하면 화면에 파일 상태와 관련된 여러 메시지가 나타난다. 작업 트리에 잇는 파일은 크게 tracked 상태와 untracked 상태로 나뉜다. 각각 무엇을 의미하는지 실습하며 알아보겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="465" data-origin-height="107"><span data-url="/assets/images/posts/a2776136d3955048394dc1c5dd02b512c6a0965c.png" data-phocus="/assets/images/posts/a2776136d3955048394dc1c5dd02b512c6a0965c.png"><img src="/assets/images/posts/a2776136d3955048394dc1c5dd02b512c6a0965c.png" loading="lazy" width="465" height="107" data-origin-width="465" data-origin-height="107"></span></figure>

가장 먼저 hello.txt에 "very Happy!!"를 추가한 후 저장해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="822" data-origin-height="230"><span data-url="/assets/images/posts/356178b4827d1ce27cf6371d3fcae97b6110319a.png" data-phocus="/assets/images/posts/356178b4827d1ce27cf6371d3fcae97b6110319a.png"><img src="/assets/images/posts/356178b4827d1ce27cf6371d3fcae97b6110319a.png" loading="lazy" width="822" height="230" data-origin-width="822" data-origin-height="230"></span></figure>

이후 hello2.txt이라는 이름으로 새 파일을 만들어 hello.txt의 내용을 한국어로 번역한 내용을 작성해 주었다.

현재 hello.txt 파일과 hello2.txt 파일 모두 작업 트리에 있다. git status 명령을 사용해 어떤 상태인지 확인해 보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="470" data-origin-height="231"><span data-url="/assets/images/posts/c945e89d5464c4993d85bb1ab49edc071ded9d3e.png" data-phocus="/assets/images/posts/c945e89d5464c4993d85bb1ab49edc071ded9d3e.png"><img src="/assets/images/posts/c945e89d5464c4993d85bb1ab49edc071ded9d3e.png" loading="lazy" width="470" height="231" data-origin-width="470" data-origin-height="231"></span></figure>

이전에 커밋했던 hello.txt 파일은 "Changes not staged for commit"이라고 되어 있다. 즉 변경된 파일이 아직 스테이지에 올라가지 않았다는 뜻이다. 그리고 파일 이름 앞에 'modified'라고 되어 있어 hello.txt가 수정되었다는 것을 알 수 있다. 이렇게 깃은 한 번이라도 커밋한 파일은 계속해서 수정 사항이 잇는지 추적한다는 사실을 알 수 있다. 이때 깃이 추적하고 있다는 뜻에서 <strong>tracked</strong> 파일이라고 한다.

반면에 hello2.txt 파일 앞에는 아무것도 없고 바로 위에는 'Untracked files'이라고 되어 있다. hello2.txt 파일은 한 번도 커밋하지 않았으므로 수정 내역을 추적하지 않는다. 그래서 <strong>untracked</strong> 파일이라고 표시한다.

> git add .
{: data-ke-style="style3"}

git add 명령 다음에 파일 이름 대신 마침표(.)를 사용하면 작업 트리에 있는 수정 파일들을 스테이지에 한꺼번에 올릴 수 있다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="373" data-origin-height="126"><span data-url="/assets/images/posts/44a4bbd25ab3e674d7623aee6aa5f2890be07a83.png" data-phocus="/assets/images/posts/44a4bbd25ab3e674d7623aee6aa5f2890be07a83.png"><img src="/assets/images/posts/44a4bbd25ab3e674d7623aee6aa5f2890be07a83.png" loading="lazy" width="373" height="126" data-origin-width="373" data-origin-height="126"></span></figure>

git status를 사용해 상태를 확인해 보았다. 마지막 버전 이후에 수정한 hello.txt는 'modified'로, 한 번도 버전 관리를 하지 않은 hello2.txt는 'new file'로 표시되는 것을 확인할 수 있다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="352" data-origin-height="72"><span data-url="/assets/images/posts/fe9fa1cb29cf7ea675553b9f6117879f1f1f0ecf.png" data-phocus="/assets/images/posts/fe9fa1cb29cf7ea675553b9f6117879f1f1f0ecf.png"><img src="/assets/images/posts/fe9fa1cb29cf7ea675553b9f6117879f1f1f0ecf.png" loading="lazy" width="352" height="72" data-origin-width="352" data-origin-height="72"></span></figure>

이제 커밋을 해주겠다. 이 커밋에는 hello.txt를 수정한 내용과 새로 만든 hello2.txt 내용이 모두 포함된다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="443" data-origin-height="312"><span data-url="/assets/images/posts/9912283e44390bc73626f573eefeacf9a54e545d.png" data-phocus="/assets/images/posts/9912283e44390bc73626f573eefeacf9a54e545d.png"><img src="/assets/images/posts/9912283e44390bc73626f573eefeacf9a54e545d.png" loading="lazy" width="443" height="312" data-origin-width="443" data-origin-height="312"></span></figure>

git log명령어를 통해 'add hello2.txt'라는 메시지를 붙인 커밋을 확인할 수 있다. 그런데 커밋마다 어떤 파일이 관련되어 있는지 알 수없다는 문제가 있다.

커밋과 관련된 파일까지 함께 살펴보려면 git log 명령에 --stat 옵션을 사용한다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="445" data-origin-height="477"><span data-url="/assets/images/posts/2a9bf36d42dde709d39be7273123c9d8ff9658c9.png" data-phocus="/assets/images/posts/2a9bf36d42dde709d39be7273123c9d8ff9658c9.png"><img src="/assets/images/posts/2a9bf36d42dde709d39be7273123c9d8ff9658c9.png" loading="lazy" width="445" height="477" data-origin-width="445" data-origin-height="477"></span></figure>

가장 최근 커밋부터 순서대로 커밋 메시지와 관련 파일이 나열된다. add hello2.txt 커밋은 hello.txt, hello2.txt 파일이 관련되어 있고, add Good bye&#126;는 hello.txt 파일과 관련되었다는 것을 알 수 있다.

#### <strong>unmodified, modified, stage 상태</strong>

파일이 tracked 상태라면 깃 명령으로 현재 작업 트리에 있는지, 스테이지에 있는지 등 더 구체적으로 알 수 있다. 깃의 커밋 과정에서 tracked 파일의 상태가 어떻게 바뀌는지 확인해 보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="380" data-origin-height="127"><span data-url="/assets/images/posts/ba9b35233862290a98679557961a839cbdd8ac58.png" data-phocus="/assets/images/posts/ba9b35233862290a98679557961a839cbdd8ac58.png"><img src="/assets/images/posts/ba9b35233862290a98679557961a839cbdd8ac58.png" loading="lazy" width="380" height="127" data-origin-width="380" data-origin-height="127"></span></figure>

ls -la 명령을 사용하여 spact 디렉터리를 살펴보면 앞에서 버전을 저장한 hello.txt와 hello2.txt파일이 있다. 여기에서는 hello2.txt 파일의 상태를 따라가 보겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="298" data-origin-height="62"><span data-url="/assets/images/posts/3701347877db4d6fb8c721a073a2bd47a7674a2e.png" data-phocus="/assets/images/posts/3701347877db4d6fb8c721a073a2bd47a7674a2e.png"><img src="/assets/images/posts/3701347877db4d6fb8c721a073a2bd47a7674a2e.png" loading="lazy" width="298" height="62" data-origin-width="298" data-origin-height="62"></span></figure>

git status 명령을 사용해 깃과 파일의 상태를 확인해 보았다. 작업 트리에 아무 변경 사항이 없다. 'working tree clean'이라고 나타나면 현재 작업 트리에 있는 모든 파일의 상태는 <strong>unmodified</strong>라는 뜻이다.(이때 <strong>unmodified</strong>는 수정되지 않은 상태를 뜻한다.)

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="297" data-origin-height="102"><span data-url="/assets/images/posts/dacfd7f96f4f98152d14975cc548ac9eb5fd0f07.png" data-phocus="/assets/images/posts/dacfd7f96f4f98152d14975cc548ac9eb5fd0f07.png"><img src="/assets/images/posts/dacfd7f96f4f98152d14975cc548ac9eb5fd0f07.png" loading="lazy" width="297" height="102" data-origin-width="297" data-origin-height="102"></span></figure>

hello2.txt을 수정하기 위해 첫 번째 줄만 남기고 모두 지운 후 저장하였다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="454" data-origin-height="182"><span data-url="/assets/images/posts/fad076d9d96969db83edd7d06fbb272de0ba38e3.png" data-phocus="/assets/images/posts/fad076d9d96969db83edd7d06fbb272de0ba38e3.png"><img src="/assets/images/posts/fad076d9d96969db83edd7d06fbb272de0ba38e3.png" loading="lazy" width="454" height="182" data-origin-width="454" data-origin-height="182"></span></figure>

다시 git status 명령을 실행해 주었다. hello2.txt 파일이 수정되었고 아직 스테이지에 올라가지 않았다고 나타난다. 'Changes not staged for commit'라는 메시지가 나타나면 파일이 수정만 된 <strong>modified</strong> 상태를 뜻한다.

> git add hello2.txt  
> git status
{: data-ke-style="style3"}

위와 같이 git add 명령을 사용해 스테이지에 올리고 git status 명령을 실행해 보았다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="388" data-origin-height="101"><span data-url="/assets/images/posts/3f35f027a257dfbf26981fd4313310433ce081ef.png" data-phocus="/assets/images/posts/3f35f027a257dfbf26981fd4313310433ce081ef.png"><img src="/assets/images/posts/3f35f027a257dfbf26981fd4313310433ce081ef.png" loading="lazy" width="388" height="101" data-origin-width="388" data-origin-height="101"></span></figure>

커밋할 변경 사항이 있다고 한다. 'Changes to be committed'라는 메시지가 나타나면 커밋 직전 단계, 즉 <strong>staged</strong> 상태이다.

> git commit -m "delete 2,3 line"  
> git status
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="289" data-origin-height="62"><span data-url="/assets/images/posts/49a5baaac3e454dd7fc4418e5ef62b3440e1fdf6.png" data-phocus="/assets/images/posts/49a5baaac3e454dd7fc4418e5ef62b3440e1fdf6.png"><img src="/assets/images/posts/49a5baaac3e454dd7fc4418e5ef62b3440e1fdf6.png" loading="lazy" width="289" height="62" data-origin-width="289" data-origin-height="62"></span></figure>

스테이지에 있는 hello2.txt 파일을 커밋하고, git status 명령을 실행해 주었다. 커밋을 끝내고 나면 hello2.txt 파일의 상태는 수정하기 직전인 unmodified 상태로 돌아간다.
