### <strong>#브랜치 톺아보기</strong>

모든 버전 관리 시스템에는 '브랜치(branch)'라는 개념이 있다. 브랜치는 원래 나뭇가지라는 뜻이다. 버전 관리 시스템에서는 나무가 가지에서 새 줄기를 뻗듯이 여러 갈래로 퍼지는 데이터 흐름을 가리키는 말로 사용한다. 이제 브랜치에 대해 자세히 알아보자.

#### <strong>브랜치가 필요한 이유</strong>

브랜치는 개발 작업에서 매우 유용한 기능이다. 메인 코드는 main 브랜치에 그냥 둔 상태로 새로 추가하는 기능이나 코드 수정 사항은 새 브랜치로 만들어서 작업할 수 있다. 만약 기능을 추가하거나 오류를 수정할 경우 처음부터 메인 코드에 작성한다고 생각해 보자. 메인 코드를 여러 번 수정하다가 원래 코드마저 엉뚱하게 바뀌거나 더 큰 오류가 일어날 수 있다. 그래서 이런 경우에는 기존 메인 코드에서 브랜치를 따로 만들어 기능을 추가하거나 오류를 수정한 후 그 브랜치 안에서 모든 것이 해결되면 그때 main 브랜치에 병합하는 방식을 사용한다.

#### <strong>브랜치 기능 살펴보기</strong>

깃으로 버전 관리를 시작하면 기본적으로 main 브랜치가 만들어진다. 사용자가 커밋할 때마다 main 브랜치는 어떤 게 최신 커밋인지 정보가 들어 있다.

만약 새 브랜치를 만든다고 생각해 보자. 기존 파일은 main 브랜치에 그대로 유지하면서, 새 브랜치에서 기존 파일 내용을 수정하거나 새로운 기능을 추가할 수 있다. 이렇게 main 브랜치에서 새 브랜치를 만드는 것을 분기한다(branch)라고 한다.

새 브랜치에서 작업을 다 끝냈다면 새 브랜치에 있던 파일을 원래 main 브랜치에 합칠 수 있다. 이렇게 분기했던 브랜치를 main 브랜치에 합치는 것을 병합한다(merge)고 한다. 즉, 기본 파일은 main 브랜치에 그대로 둔 상태에서 새로운 브랜치를 분기한 후 수정이나 추가 작업을 하고 별문제 없이 완성되었다면, 새 브랜치의 내용을 main 브랜치와 병합하는 것이다.

### <strong>#브랜치 만들기 및 이동하기</strong>

브랜치가 무엇인지, 어떤 기능을 하는지 알아보았으니 이제 실습을 통해서 어떻게 사용하는지 알아보자.

#### <strong>실습 상황 만들기</strong>

먼저 브랜치 분기가 필요한 상황을 만들어 보자. 먼저 디렉터리를 만들고 그 안에 텍스트 파일을 하나 만들어보겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="905" data-origin-height="282"><span data-url="/assets/images/posts/a9302f844f127fd2dcbba65bac66e4a289af912e.png" data-phocus="/assets/images/posts/a9302f844f127fd2dcbba65bac66e4a289af912e.png"><img src="/assets/images/posts/a9302f844f127fd2dcbba65bac66e4a289af912e.png" loading="lazy" width="905" height="282" data-origin-width="905" data-origin-height="282"></span></figure>

> git init
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="457" data-origin-height="62"><span data-url="/assets/images/posts/29e2b106ef300f0b83cead9764b33f4b1b505b42.png" data-phocus="/assets/images/posts/29e2b106ef300f0b83cead9764b33f4b1b505b42.png"><img src="/assets/images/posts/29e2b106ef300f0b83cead9764b33f4b1b505b42.png" loading="lazy" width="457" height="62" data-origin-width="457" data-origin-height="62"></span></figure>

manuals라는 새 디렉터리를 만들고 작업 폴더로 추가해 주었다. 그다음 manuals에서 깃을 사용하려면 저장소로 바꿔야 한다. 이를 초기화라고 한다. 초기화하는 방법은 git init이라고 입력해 주면 된다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="820" data-origin-height="152"><span data-url="/assets/images/posts/f66e69bc199f53418f7d718ce4320ca100f396c4.png" data-phocus="/assets/images/posts/f66e69bc199f53418f7d718ce4320ca100f396c4.png"><img src="/assets/images/posts/f66e69bc199f53418f7d718ce4320ca100f396c4.png" loading="lazy" width="820" height="152" data-origin-width="820" data-origin-height="152"></span></figure>

다음으로 work.txt라는 파일을 하나 생성해 준 뒤 'content 1'이라는 내용을 추가하여 저장해 주었다.

> git add work.txt  
> git commit -m "work1"
{: data-ke-style="style3"}

이제 work.txt 파일을 스테이지에 올리고 커밋해 주었다. 커밋 메시지는 'work1'이라고 간단하게 작성해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="445" data-origin-height="109"><span data-url="/assets/images/posts/9b840061e877bbc782879df5dc5c7d0619745192.png" data-phocus="/assets/images/posts/9b840061e877bbc782879df5dc5c7d0619745192.png"><img src="/assets/images/posts/9b840061e877bbc782879df5dc5c7d0619745192.png" loading="lazy" width="445" height="109" data-origin-width="445" data-origin-height="109"></span></figure>

커밋이 완료된 후 git log를 입력해서 커밋 내역을 확인해 보았다. 커밋 해시 오른쪽에 있는 (HEAD -&gt; main)은 HEAD가 현재 main이라는 브랜치를 가리키고 있다는 뜻이다. 그리고 (HEAD -&gt; main)이 붙은 커밋이 가장 최신 커밋이다. 현재는 work 1이라는 커밋이 최신 커밋이라고 알려주고 있다.

이제 work.txt 파일을 두 번 더 커밋해 보겠다. 'content 2' 내용을 추가 후 'work2'라는 메시지로 커밋하고, 'content 3' 내용을 추가 후 'work3'라는 메시지로 커밋해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="444" data-origin-height="316"><span data-url="/assets/images/posts/34b7d94eec01d7eebe7f6fa982183774b41082b5.png" data-phocus="/assets/images/posts/34b7d94eec01d7eebe7f6fa982183774b41082b5.png"><img src="/assets/images/posts/34b7d94eec01d7eebe7f6fa982183774b41082b5.png" loading="lazy" width="444" height="316" data-origin-width="444" data-origin-height="316"></span></figure>

마지막으로 커밋 로그를 다시 한번 더 확인해 주었다. git log를 입력하니 3개의 커밋이 만들어졌고, 가장 최신 커밋인 work3에 (HEAD -&gt; main)가 표시되어 있는 것을 확인할 수 있다.

#### <strong>새 브랜치 만들기</strong>

깃에서 브랜치를 만들거나 확인하는 명령은 git branch이다.

> git branch
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="201" data-origin-height="50"><span data-url="/assets/images/posts/d89e1c02bd66e6dacd9a3d304071235689345380.png" data-phocus="/assets/images/posts/d89e1c02bd66e6dacd9a3d304071235689345380.png"><img src="/assets/images/posts/d89e1c02bd66e6dacd9a3d304071235689345380.png" loading="lazy" width="201" height="50" data-origin-width="201" data-origin-height="50"></span></figure>

git branch라고 입력해 보면 main이라고 나타난다. 저장소를 만들면 main 브랜치가 기본으로 생성되고, 지금까지 main 브랜치에서 작업하고 있었던 것이다.

이제 새로운 브랜치를 만들어보자.

> git branch \[branch name\]
{: data-ke-style="style3"}

새로운 브랜치를 만들려면 git branch 명령 다음에 만들려는 브랜치 이름을 적는다. 나는 한번 spact라는 이름의 브랜치를 만들어보겠다.

새로운 브랜치를 만들어도 화면에는 아무것도 나타나지 않는다. 내가 만든 브랜치가 제대로 만들어졌는지 확인해 보기 위해 git brach 명령어로 확인해 주었다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="263" data-origin-height="62"><span data-url="/assets/images/posts/97d95fe7d9d83bdb3d22358b34c1080aec8aae58.png" data-phocus="/assets/images/posts/97d95fe7d9d83bdb3d22358b34c1080aec8aae58.png"><img src="/assets/images/posts/97d95fe7d9d83bdb3d22358b34c1080aec8aae58.png" loading="lazy" width="263" height="62" data-origin-width="263" data-origin-height="62"></span></figure>

main 브랜치 위에 spact 브랜치가 추가된 것을 확인할 수 있다. main 앞에 \* 가 표시된 것은 여러 브랜치 가운데 현재 작업하는 브랜치를 나타낸다. 즉, 아직 나는 main 브랜치에서 작업하고 있다는 뜻이다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="514" data-origin-height="313"><span data-url="/assets/images/posts/01aed407aaf68fb08596d64978fc6aa6fba2593f.png" data-phocus="/assets/images/posts/01aed407aaf68fb08596d64978fc6aa6fba2593f.png"><img src="/assets/images/posts/01aed407aaf68fb08596d64978fc6aa6fba2593f.png" loading="lazy" width="514" height="313" data-origin-width="514" data-origin-height="313"></span></figure>

브랜치가 추가된 후에는 커밋 로그 화면도 다르게 나타난다. git log 명령을 사용해 커밋 로그를 확인해 보았다. 그동안 커밋 로그를 확인할 때 (HEAD -&gt; main)라고 표시되던 곳에 spact 브랜치가 추가되면서 (HEAD -&gt; main, spact)로 바뀌었다. 저장소에 main과 spact라는 2개의 브랜치가 있고, HEAD -&gt; main 이므로 현재 작업하는 브랜치는 main 브랜치라는 의미이다.

이번엔 추가로 doit 브랜치와 github 브랜치를 만들어주겠다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="138" data-origin-height="87"><span data-url="/assets/images/posts/ab2fc2cfb30f2cd4a8f5bf684a3a3dc65627b6cb.png" data-phocus="/assets/images/posts/ab2fc2cfb30f2cd4a8f5bf684a3a3dc65627b6cb.png"><img src="/assets/images/posts/ab2fc2cfb30f2cd4a8f5bf684a3a3dc65627b6cb.png" loading="lazy" width="138" height="87" data-origin-width="138" data-origin-height="87"></span></figure>

그리고 이후 git branch 명령어를 통해 살펴보면 잘 추가가 된 것을 확인할 수 있다.

#### <strong>IF 새 커밋을 추가한다면?</strong>

main 외에 3개의 브랜치를 추가했고, 현재 최신 커밋은 work3이다. 이 상태에서 새로운 커밋을 추가하면 어떻게 되는지 알아보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="601" data-origin-height="314"><span data-url="/assets/images/posts/7f6fd39877a842d4ee93c97ca95857180ad4a3e0.png" data-phocus="/assets/images/posts/7f6fd39877a842d4ee93c97ca95857180ad4a3e0.png"><img src="/assets/images/posts/7f6fd39877a842d4ee93c97ca95857180ad4a3e0.png" loading="lazy" width="601" height="314" data-origin-width="601" data-origin-height="314"></span></figure>

git log로 확인해 보면 work3 커밋 해시의 오른쪽에 main 브랜치를 비롯해 spact, github, doit 브랜치가 함께 표시되어 있다. 즉, 이것은 main 브랜치뿐만 아니라 spact, github, doit 브랜치 모두 최신 커밋이 work3이라는 뜻이다.

<figure class="imagegridblock"><div class="image-container"><span data-url="/assets/images/posts/b42aeb45d2e7b431760bb327cda514913e929122.png" data-phocus="/assets/images/posts/b42aeb45d2e7b431760bb327cda514913e929122.png" data-origin-width="296" data-origin-height="123" data-is-animation="false" style="width: 31.0364%; margin-right: 10px;" data-widthpercent="31.4"><img src="/assets/images/posts/b42aeb45d2e7b431760bb327cda514913e929122.png" loading="lazy" width="296" height="123"></span><span data-url="/assets/images/posts/2f6ddfb262090e6ad10d9d60c7686744325b791b.png" data-phocus="/assets/images/posts/2f6ddfb262090e6ad10d9d60c7686744325b791b.png" data-origin-width="368" data-origin-height="70" data-is-animation="false" style="width: 67.8008%;" data-widthpercent="68.6"><img src="/assets/images/posts/2f6ddfb262090e6ad10d9d60c7686744325b791b.png" loading="lazy" width="368" height="70"></span></div></figure>

현재 나는 main 브랜치에 있다. 커밋을 하나 만들어서 어떻게 달라지는지 확인해 보자. work.txt 파일 안에 'main content 4'라는 내용을 추가한 후 'main work4'라는 메시자와 함께 커밋해 보았다.

main 브랜치에 새로운 커밋이 추가되었다. 그럼 로그는 어떻게 바뀌었을지 확인해 보자.

> git log --oneline
{: data-ke-style="style3"}

git log 명령에 --oneline 옵션을 추가해서 확인해 주었다. --oneline 옵션은 한 줄에 한 커밋씩 보여주기 때문에 여러 커밋을 한눈에 확인할 때 편리하다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="307" data-origin-height="93"><span data-url="/assets/images/posts/5da629ccf580468fdb13d41aca393b47a44b8159.png" data-phocus="/assets/images/posts/5da629ccf580468fdb13d41aca393b47a44b8159.png"><img src="/assets/images/posts/5da629ccf580468fdb13d41aca393b47a44b8159.png" loading="lazy" width="307" height="93" data-origin-width="307" data-origin-height="93"></span></figure>

최신 커밋인 main work 4는 main 브랜치에만 적용되어 있고 spact, github, doit 브랜치는 아직 work 3 커밋 상태이다. 즉, 새로 만든 커밋은 현재 브랜치(main 브랜치)에만 적용되고 나머지 브랜치에는 적용되지 않는다. 따라서 브랜치별로 커밋을 따로 관리할 수 있다는 사실을 알았다.

#### <strong>브랜치 전환하기 - git switch</strong>

브랜치가 여러 개라면 브랜치마다 서로 다른 커밋을 만들 수 있다. 그렇다면 브랜치마다 오가면서 작업하는 게 편할 것이다. 현재 브랜치에서 다른 브랜치로 이동하는 것을 브랜치를 전환하다고 하고 git switch 명령을 사용한다. 깃 이전 버전에서는 브랜치 간에 이동할 대 checkout 명령을 사용했기 때문에 브랜치를 바꾸는 것을 '체크아웃한다'라고도 말한다. 그래서 브랜치를 전환하는 것과 브랜치를 체크아웃한다는 것은 같은 말이다. 이제 실습을 통해 알아보자.

현재 브랜치에서 다른 브랜치로 전환하려면 git switch 명령 다음에 전환할 브랜치 이름을 사용한다. 

> git switch \[branch name\]
{: data-ke-style="style3"}

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="250" data-origin-height="49"><span data-url="/assets/images/posts/b7a458b21cce9620e47e071a68e9bec1e3060ed8.png" data-phocus="/assets/images/posts/b7a458b21cce9620e47e071a68e9bec1e3060ed8.png"><img src="/assets/images/posts/b7a458b21cce9620e47e071a68e9bec1e3060ed8.png" loading="lazy" width="250" height="49" data-origin-width="250" data-origin-height="49"></span></figure>

git switch 명령을 사용해서 spact 브랜치로 전환해 주었다.

이후 $ 커서 바로 위에 나타난 파일 경로 끝에 (spact)이라고 표시될 것이다. 현재 spact 브랜치에서 작업하고 있다는 뜻이다. 이제 spact 브랜치로 바꿨을 대 어떤 변화가 생기는지 확인해 보자. 

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="364" data-origin-height="74"><span data-url="/assets/images/posts/e95541c579076698d44c5c691871e34e02141e18.png" data-phocus="/assets/images/posts/e95541c579076698d44c5c691871e34e02141e18.png"><img src="/assets/images/posts/e95541c579076698d44c5c691871e34e02141e18.png" loading="lazy" width="364" height="74" data-origin-width="364" data-origin-height="74"></span></figure>

git log 명령을 사용해서 현재 브랜치의 커밋 로그를 확인해 주었다. spact 브랜치를 만들기 전까지 main 브랜치에 있던 커밋들은 그대로 spact 브랜치에도 적용된 것을 확인할 수 있다. 그래서 work3 커밋까지 표시된다. 커밋 해시에서 HEAD가 spact을 가리키는 것도 확인할 수 있다.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="380" data-origin-height="104"><span data-url="/assets/images/posts/3934b24b592ba0fc898d7ef2bfa56f180c277210.png" data-phocus="/assets/images/posts/3934b24b592ba0fc898d7ef2bfa56f180c277210.png"><img src="/assets/images/posts/3934b24b592ba0fc898d7ef2bfa56f180c277210.png" loading="lazy" width="380" height="104" data-origin-width="380" data-origin-height="104"></span></figure>

편집 창에서 work.txt를 확인했을 때 contnet1부터 content3까지 3개의 행만 보인다. main content 4는 spact 브랜치를 분기한 후에 main 브랜치에 추가된 커밋이어서 spact 브랜치에 영향을 미치지 않는다는 것을 알 수 있다.
