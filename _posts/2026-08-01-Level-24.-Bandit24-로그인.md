오늘은 Bandit24 문제를 해결해보려고 한다.

이번 문제의 정보를 정리해 보면 아래와 같다.

> 1\. 일정 기간을 두고 그 기간마다 실행되게 만드는 cron이 실행되고 있다.  
> 2\. cron설정 파일이 /etc/cron.d/ 디렉터리에 있다.  
> 3\. /etc/cron.d/ 디렉터리에서 설정 파일을 확인하고 어떤 명령이 실행되고 있는지 살펴봐라.
{: data-ke-style="style3"}

즉, 이번 문제도 지난 문제와 동일한 방식의 문제라고 판단할 수 있다.

그렇다면 지난번과 같이 /etc/cron.d/ 디렉터리로 가서 살펴보자.

<figure class="imageblock alignCenter" data-ke-mobilestyle="widthOrigin" data-origin-width="806" data-origin-height="517"><span data-url="/assets/images/posts/f73c0648e6862df373ea0a5b9ad02d56a8920122.png" data-phocus="/assets/images/posts/f73c0648e6862df373ea0a5b9ad02d56a8920122.png"><img src="/assets/images/posts/f73c0648e6862df373ea0a5b9ad02d56a8920122.png" loading="lazy" width="806" height="517" data-origin-width="806" data-origin-height="517"></span></figure>

지난번과 동일한 방식으로 cronjob\_bandit24 파일을 읽은 후 /usr/bin/cronjob\_bandit24.sh 스크립트를 읽어보면 작성된 스크립트를 확인할 수 있다.

한번 이 코드를 분석해 보자.

```bash
#!/bin/bash

shopt -s nullglob

myname=$(whoami)

cd /var/spool/"$myname"/foo || exit
echo "Executing and deleting all scripts in /var/spool/$myname/foo:"
for i in * .*;
do
    if [ "$i" != "." ] && [ "$i" != ".." ];
    then
        echo "Handling $i"
        owner="$(stat --format "%U" "./$i")"
        if [ "${owner}" = "bandit23" ] && [ -f "$i" ]; then
            timeout -s 9 60 "./$i"
        fi
        rm -rf "./$i"
    fi
done
```

먼저 3번째 줄인 shopt -s nullglob의 경우 Bash의 nullglob 옵션을 활성화한다는 뜻이다. 원래 와일드카드(\*) 패턴에 매칭되는 파일이 없으면 Bash는 \* 문자 자체를 문자열로 취급한다. 하지만 nullglob을 켜면 매칭되는 파일이 없을 경우 빈 문자열로 처리되어 for 루프가 실행되지 않고 안전하게 지나간다.

다음으로 5번째 줄인 myname=$(whoami)의 경우 지난 레벨에서 본 것과 동일하다. 이때 $(whoami)는 bandit24가 되겠다.

7번째 줄인 cd /var/spool/"$myname"/foo || exit은 $(whoami) 값을 적용시켜서 cd /var/spool/bandit24/foo || exit가 되겠다. 이 명령어는 /var/spool/bandit24/foo 디렉터리로 이동하고 만약 해당 디렉터리가 존재하지 않거나 권한 문제로 이동에 실패하면 스크립트를 즉시 종료한다. 따라서 cd명령어를 통해 디렉터리를 변경하고 이후 존재하는 모든 스크립트를 실행하고 있는 것이다. (바로 다음 줄인 echo "Executing and deleting all scripts in /var/spool/$myname/foo:"를 통해 알 수 있다.)

이제 for문을 자세하게 살펴보자.

```bash
for i in * .*;
do
    if [ "$i" != "." ] && [ "$i" != ".." ];
    then
        echo "Handling $i"
        owner="$(stat --format "%U" "./$i")"
        if [ "${owner}" = "bandit23" ] && [ -f "$i" ]; then
            timeout -s 9 60 "./$i"
        fi
        rm -rf "./$i"
    fi
done
```

먼저 for i in \* .\*;의 경우 해당 디렉터리 안의 모든 파일과 숨김파일을 하나씩 변수 i에 담아 반복문을 돌린다는 의미이다.

if \[ "$i" != "." \] &amp;&amp; \[ "$i" != ".." \]; then의 경우 숨김파일 패턴에 반드시 포함되는 .(현재 디렉터리)와 ..(상위 디렉터리)를 처리대상에서 제외한다. 그 이유는 이 조건무이 없다면 상위 디렉터리 전체를 삭제하려 시도하는 버그가 발생하기 때문이다.

echo "Handling $i"은 현재 검사 중인 파일 혹은 디렉터리의 이름을 출력하는 코드이다.

owner="$(stat --format "%U" "./$i")"에서 stat --format "%U" "./$i"은 파일 혹은 디렉터리의 소유자 사용자 이름만 추출하는 명령어로 변수 owner에 파일 $i의 소유자 이름을 저장한다.

if \[ "${owner}" = "bandit23" \] &amp;&amp; \[ -f "$i" \]; then timeout -s 9 60 "./$i" fi에서 \[ "${owner}" = "bandit23" \]를 통해 파일 소유자가 bnadit23인지 확인한 후 \[ -f "$i" \]로 해당 항목이 디렉터리가 아닌 일반 파일인지 확인한다. 또한 timeout -s 9 60 "./$i"를 통해 두 조건이 모두 참이면 해당 파일($i)을 실행한다. 단, 무한 루프나 멈춤 현상을 막기 위해 최대 60초 간만 실행하며, 60초가 넘어가면 강제 종료 시그널(-s 9)을 보내 프로세스를 kill 한다.

rm -rf "./$i" 코드를 통해 조건에 만족 하든 못하든 검사한 항목(./$i)을 강제로 무조건 삭제한다.(-r : 디렉터리 재귀 삭제, -f : 강제 삭제)

코드의 흐름을 아래와 같이 간단히 정리해 보았다.

> 1.cd /var/spool/bandit24/foo로 이동하여 해당 디렉터리에 있는 모든 스크립트를 하나씩 가져와서 실행한다.  
> 2\. 실행한 후 삭제한다.
{: data-ke-style="style3"}

그렇다면 cd /var/spool/bandit24/foo에 있는 스크립트는 다 실행시킨다는 의미가 된다. 그럼 만약 cd /var/spool/bandit24/foo에 bandit24의 비밀번호를 /tmp/\[디렉터리\]에 저장하라는 코드를 넣어주게 되면 위에서 분석한 스크립트는 bandit24 권한이기 때문에 읽어낼 수 있을 것이다. 그럼 한번

cd /var/spool/bandit24/foo 디렉터리로 들어가 보자.

cd /var/spool/bandit24/foo 디렉터리로 들어가면 파일을 만들 수 있다. 파일을 만들기 위해서 echo "cat /etc/bandit\_pass/bandit24 &gt; /tmp/spactcode" &gt; spactcode.sh라고 작성해 주었다. 이 코드는 cat /etc/bandit\_pass/bandit24를 통해 읽은 bandit24 비밀번호를 /tmp/spact로 저장하는 것을 출력해라. 이것을 spact.sh로 저장하겠다는 것이다. 또한 /etc/bandit\_pass/bandit24 &gt; /tmp/spactcode" &gt; spactcode.sh가 실행되려면 실행권한이 필요하므로 777 권한을 부여해 주었다. 여기서 777은 rwx 모든 권한을 다 주겠다는 것이다.

이제 권한까지 주었으면 기다리면 된다. 매 분마다 열심히 분석한 스크립트가 실행되기 때문이다.

1분이 지나면 만들었던 shell파일이 삭제가 된 것을 확인할 수 있다. 삭제가 되었다는 것은 /tmp/spactcode에 비밀번호가 들어갔다는 의미가 된다.

cat 명령어로 /tmp/spactcode를 읽어보면 비밀번호가 나오게 되면서 해당 문제는 끝이 난다.
